# 交互状态与联动检查

这是一份按任务选用的检查清单，不是必须新增的功能列表。没有用户依据的业务规则标记待确认；不为了覆盖清单而扩展范围。

| 关注点 | 需要决定的内容 |
| --- | --- |
| 初始状态 | 初始可见内容、默认值、可操作项是否符合已确认需求 |
| 触发与退出 | 点击、输入或选择后发生什么；关闭、取消、返回分别保留还是丢弃哪些临时状态 |
| 控件联动 | 上游值变化时，下游可选项、选择值、结果集合如何保持一致；状态尽量只有一个可信来源 |
| 提交与反馈 | 校验失败是否保留输入，成功反馈是否对应实际发生的本地行为；不要伪造接口成功 |
| 空与边界状态 | 搜索无结果、取消选择、重复操作或长内容对该需求是否相关；相关时如何反馈 |
| 页面关系 | 结果占据普通布局还是覆盖展示，滚动属于哪个容器；从实际上下文决定，不默认全局固定定位 |
| 可操作性 | 表单有可理解标签，按钮语义明确，浮层的关闭与焦点行为使用现有组件能力 |

验收项写成用户能操作和观察的关系，例如“改变已确认的筛选条件后，结果与条件一致”，而不是限定工具顺序、业务 class 或内部 DOM。未知数据、规则和阈值不自行编造；模拟数据需明确标识。
