# UI 辅助需求编写插件优化记录

## O-001：将高频迭代界面改为服务端直出

**状态：** 待排期  
**优先级：** 中  
**提出日期：** 2026-09-02

### 背景与目标

当前侧边栏对话界面、副本管理和日志页面均随 Chrome 插件打包发布。界面样式、交互细节或文案调整后，需要重新构建、分发并由使用者更新插件，迭代成本较高。

目标是在不牺牲浏览器能力与安全边界的前提下，将高频变化的业务 UI 由服务端直出；后续常规界面更新仅部署服务端，无需重新分发插件。

### 方案边界

保留插件作为稳定的浏览器能力层，负责：

- 选取页面元素、注入内容脚本、截图和打开/切换标签页；
- 保存安装凭证，并代理需要鉴权的服务端请求；
- 校验远程页面来源，并提供受控的消息桥接。

服务端负责直出可高频迭代的业务界面，包括侧边栏对话、执行进度、需求澄清、副本管理和日志查看。

远程 UI 不能直接获得扩展权限或安装令牌。涉及浏览器能力和鉴权请求时，远程 UI 通过定义明确的消息协议请求插件壳，由插件壳完成校验和执行后返回结果。

### 约束与验收标准

- 第一阶段不新增服务端运行时 npm 依赖；前端资源可在行外构建为静态产物并随服务发布。
- 仅调整样式、文案、普通业务交互时，服务端发布后即可生效，不要求用户更新插件。
- 新增 Chrome 权限、修改内容脚本/后台脚本、扩展与服务端桥接协议或安全修复时，仍需发布插件新版本。
- 消息来源、请求类型和参数均需白名单校验；不得向远程页面暴露长期安装令牌。
- 当远程 UI 与插件桥接协议版本不兼容时，应明确提示升级插件，不能静默降级或执行未知请求。

### 建议实施顺序

1. 先迁移侧边栏主界面，验证远程 UI 与插件桥接、鉴权代理和版本兼容机制。
2. 再迁移副本管理与日志页面，统一服务端静态资源发布方式。
3. 稳定后将插件包收敛为浏览器能力层，减少后续插件发版范围。
