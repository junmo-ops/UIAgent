# 环境变量梳理与精简建议

实施状态：以下盘点保留为迁移对照，普通参数迁移现已完成；当前生效配置以[服务配置说明](服务配置说明.md)为准。

日期：2026-09-23。范围：当前仓库自有代码实际读取的环境变量、Dockerfile 和构建脚本，不包含操作系统及第三方库支持的全部变量。盘点时未读取平台配置或本机真实密钥文件。

## 结论

建议保留“凭证走 Secret，普通业务参数走配置文件，运行环境参数由平台或镜像提供”。存储普通参数已完成迁移，其他业务参数仍在读取环境变量，不能现在直接从平台删除。

新增 `apps/agent-service/config/service.json` 管理模型、鉴权、访问地址、日志及诊断参数；保留已经实现的 `config/workspace-storage.json` 管理存储。配置文件可随部署包提供，或由平台挂载，修改后重启。插件用户不用填写。

## 1. 保留为 Secret 的变量

| 变量 | 当前作用 | 是否需要填写 |
| --- | --- | --- |
| `MODEL_API_KEY` | 模型调用凭证 | 当前远程模型启动需要 |
| `INSTALLATION_TOKEN_SECRET` | 签名安装身份及预览令牌 | installation 模式需要；保持稳定，至少 32 字符 |
| `WORKSPACE_S3_ACCESS_KEY_ID` | 对象存储凭证标识 | S3 模式需要 |
| `WORKSPACE_S3_SECRET_ACCESS_KEY` | 对象存储签名密钥 | S3 模式需要 |
| `WORKSPACE_S3_SESSION_TOKEN` | 对象存储临时凭证令牌 | 仅使用临时凭证时需要 |

因此，当前“远程模型 + installation 身份 + S3”部署，业务上通常需要管理 4 个必填凭证变量，临时存储凭证时再加 1 个。此数量是完成其他参数迁移后的目标，不是当前已经可以只配置这几个变量。

## 2. 保留为平台／运行环境变量

| 变量 | 当前默认或来源 | 建议 |
| --- | --- | --- |
| `HOST` | 源码默认 127.0.0.1；Dockerfile 设为 0.0.0.0 | 保留平台覆盖，普通部署沿用镜像默认，不必再手工重复配置 |
| `PORT` | 8787 | 保留平台覆盖，按平台端口规则配置 |
| `NODE_ENV` | Dockerfile 设置 production；鉴权据此限制开发模式 | 保留，由镜像或平台提供 |
| `NODE_EXTRA_CA_CERTS` | Node 运行时读取，自有代码不直接读取 | 仅企业证书链需要时设置 |
| `PNPM_HOME`、`PATH` | Dockerfile 为包管理器设置 | 镜像内部环境，用户通常不需要管理 |

## 3. 适合移入 service.json 的业务参数

以下参数在当前代码中仍然生效，建议新增配置读取并更新部署模板后再撤掉对应环境变量。

| 当前变量 | 当前用途／默认 | 建议文件字段 |
| --- | --- | --- |
| `MODEL_BASE_URL` | 模型服务地址；远程模式必填 | `model.baseUrl` |
| `MODEL_NAME` | 模型名称；远程模式必填 | `model.name` |
| `CLINE_MAX_ITERATIONS` | 源码编辑最大迭代次数，代码默认 45 | `model.edit.maxIterations` |
| `CLINE_MAX_OUTPUT_TOKENS` | 源码编辑单次最大输出 token，默认 8192 | `model.edit.maxOutputTokens` |
| `MODEL_MAX_ITERATIONS` | 助手路由最大迭代次数，默认 3，设置时最多 5 | `model.router.maxIterations` |
| `AUTH_MODE` | 生产默认要求外部身份；当前试点须显式 installation；开发默认 development | `auth.mode`，继续保留生产禁用开发身份保护 |
| `INSTALLATION_TENANT_ID` | 默认 internal-pilot | `auth.installation.tenantId`，迁移时必须保持原值 |
| `INSTALLATION_ADMIN_USER_IDS` | 管理员 ID 列表；默认无人拥有此权限 | 按最新要求保留环境变量，多个 ID 使用英文逗号分隔 |
| `INSTALLATION_TOKEN_TTL_SECONDS` | 默认 365 天 | `auth.installation.tokenTtlSeconds` |
| `PREVIEW_TOKEN_TTL_SECONDS` | 默认 7 天 | `auth.installation.previewTokenTtlSeconds` |
| `PUBLIC_BASE_URL` | 对外地址；未设置时从请求 URL 构造 | `http.publicBaseUrl`，反向代理部署保留明确配置 |
| `CORS_ORIGIN` | 未设置时 *；显式设置时还影响 credentials | `http.corsOrigin`，迁移保持现有语义 |
| `LOG_FILE` | 代码默认 .logs/agent-turns.jsonl；镜像设置独立目录 | `logging.file`，迁移保留实际日志路径 |
| `REPLICA_A_ENABLED` | 默认关闭，保留冻结计算样式诊断变体 | `diagnostics.replicaAEnabled`，默认 false |
| `DEV_AUTH_USER_ID` | 开发身份；默认 local-developer | 可选 `auth.development.userId`，正式部署不需要 |
| `DEV_AUTH_TENANT_ID` | 开发租户；默认 local | 可选 `auth.development.tenantId`，正式部署不需要 |

移入文件不等于硬编码，不同部署仍可提供不同文件。管理员列表不是密钥，但属于权限配置，应由有权限的部署人员维护，不能暴露成普通用户可编辑项。

## 4. 可减少或取消的开关

| 变量 | 当前事实 | 建议 |
| --- | --- | --- |
| `MODEL_MODE` | 三个 Cline 工厂要求 remote；正常启动没有可直接使用的 mock 工厂，但日志／健康信息仍有 mock 默认值 | 正式运行路径固定远程模型，移除此部署开关；保留开发测试的显式依赖注入能力 |
| `MODEL_PROVIDER` | 当前只用于日志和健康信息，实际调用由 baseUrl 与模型适配器决定 | 如需显示厂商名，改为文件中可选的 `model.providerLabel`；否则取消手工配置 |
| `WORKSPACE_IDENTITY_ISOLATION` | 默认 true，允许通过环境变量关闭隔离 | 建议生产始终隔离，去掉生产关闭入口；开发若确有用途再单独保留明确选项 |
| `ALLOW_INSECURE_DEV_AUTH` | 可在 production 下放行 development 身份 | 建议移除生产绕过入口，不搬到常规配置文件 |
| `SOURCE_WORKSPACE_DIR` | 当前仅 local 模式仍读取；S3 使用配置文件 cacheDirectory | 在本地开发路径迁移完后删除兼容覆盖，统一使用已有 cacheDirectory |

后两项鉴权建议属于行为收紧，应单独确认没有部署依赖这些开关；不能为了减少变量直接改变线上鉴权行为。

## 5. 已经从环境变量移出的存储参数

当前 Endpoint、Region、Bucket、Prefix、存储模式、缓存目录、请求超时、归档容量限制都由 `config/workspace-storage.json` 管理。之前方案里的 `WORKSPACE_STORAGE`、`WORKSPACE_S3_ENDPOINT`、`WORKSPACE_S3_REGION`、`WORKSPACE_S3_BUCKET`、`WORKSPACE_S3_PREFIX`、`WORKSPACE_S3_TIMEOUT_MS`、`WORKSPACE_ARCHIVE_MAX_*` 已不再是普通存储配置入口，不应继续添加到平台。

## 6. 构建和交付变量，不属于服务运行配置

| 变量 | 读取位置与作用 | 建议 |
| --- | --- | --- |
| `WXT_PUBLIC_AGENT_SERVICE_URL` | 插件构建时设置服务地址及匹配权限 | 放在插件构建配置／发布流水线；不是部署后修改服务环境变量就会更新插件 |
| `EXTENSION_RELEASE_NOTES` | 插件打包时写入发布说明 | 属于每次发布输入，可保留流水线变量或改发布命令参数 |
| `INTERNAL_NPM_REGISTRY` | 行内部署依赖预检脚本的源地址覆盖 | 可保留为工具选项；不需要放到服务平台运行变量中 |

## 7. 本次发现的配置歧义

- `.env.example` 中 `CLINE_MAX_ITERATIONS=30` 是注释示例，代码默认值是 45；导出示例又写 45。后续应统一默认值及文档，避免误以为默认 30。
- `MODEL_MAX_ITERATIONS` 控制的是助手路由，不是源码修改；命名容易混淆，应在文件里分开 router 与 edit。
- `MODEL_PROVIDER` 不会切换适配器协议，设置厂商名并不等于完成对应模型接入。
- 配置删除必须同步处理主仓库模板、导出模板、Dockerfile、健康接口及报错提示，避免旧示例继续要求填写已经废弃的变量。

## 8. 建议实施顺序

1. 增加有格式校验的 service.json，把普通参数读入明确的运行配置对象；模型适配器直接接收配置和独立密钥，不把配置文件重新包装成一堆环境变量。
2. 配置文件成为普通参数的唯一来源。切换前逐项对照平台实际值，特别是租户、管理员、CORS、对外地址和日志路径；不要用示例默认覆盖线上值。
3. 模型调用凭证、身份签名密钥和 S3 凭证继续从 Secret 获取。HOST、PORT、NODE_ENV 保持平台语义。
4. 单独处理固定远程模型、取消兼容缓存目录变量和鉴权开关收紧；迁移对应关系保留在文档中，运行时不检测旧变量。
5. 同步部署材料与导出脚本，做类型检查、构建和 diff 审查；不新增或运行单元测试。真实部署功能由用户验收。

后续改造已完成；旧变量不再读取、检测或提示，普通参数仅从配置文件获取。
