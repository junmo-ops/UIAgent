# 真实模型场景评测

## 目的与边界

已有确定性 E2E 验证工程链路；这套评测使用真实路由、聊天、源码编辑 Agent 和真实模型，观察需求是否被正确理解与执行。两套结果分开，不合并通过率。

首批 24 个案例是合成场景，不是生产用户请求的抽样，不能据此声称覆盖任意网页或所有用户诉求。布局使用普通流、flex、grid、定位与滚动容器。当前测试页面结构较简单，后续应补入经脱敏的真实需求和更复杂页面。

用例及逐项验收标准在 `tooling/e2e/real-cases.mjs`。这些标准为初稿，可按真实用户需求调整；不允许为了让某个案例通过而向产品代码增加文案、sourceId 或固定 DOM 特判。

2026-10-01 已完成两批实际执行，见[扩展评测结果](真实模型扩展评测结果.md)。S01 引用的旧运行验证技能当前不存在，本次标为前提不满足；后续执行前需更新该案例前提。S02 已实际使用当前需求交付技能执行 Python。

## 运行

复用已独立安装的 Playwright，不增加依赖。读取现有服务配置（本地优先）和 `apps/agent-service/.env` 中的模型凭证；不输出密钥。运行前确认本地模型地址正确、凭证有效。模型调用会产生实际费用。

默认小样本：页面问答 Q01、单轮文字修改 E01、多轮指代 M01，共 4 轮对话。

```sh
npm --prefix tooling/e2e run test:real
```

指定案例（不会自动重试）：

```sh
REAL_CASES=Q01,E02 npm --prefix tooling/e2e run test:real
```

明确需要全量时：

```sh
REAL_ALL=1 npm --prefix tooling/e2e run test:real
```

测试创建临时服务、浏览器用户目录和副本，真实插件通过侧栏提交请求。只有页面内容为合成数据；没有固定模型响应或脚本替身。真实技能案例使用服务内置技能。测试不连接 COS，不修改正式副本。

### 复杂场景批次

已执行结果见[复杂场景真实模型评测结果](复杂场景真实模型评测结果.md)，其中包含真实布局失败和测试定位误报的区分。

`tooling/e2e/complex-cases.mjs` 单独定义 16 个复杂场景及 6 个合成页面，包含嵌套布局、滚动与固定导航、420px 窄窗口、相似卡片定位、澄清后继续执行、多轮局部撤回、折叠详情与本地表单。总计 23 轮计划对话，失败时可能提前终止。与基础 24 例分开选取，不改变默认小样本和 `REAL_ALL=1` 的基础集。

```sh
REAL_SUITE=complex npm --prefix tooling/e2e run test:real
# 单例诊断（仍有模型调用费用）
REAL_SUITE=complex REAL_CASES=C11 npm --prefix tooling/e2e run test:real
# 明确内外位置、原生点击澄清选项后继续执行
REAL_SUITE=complex REAL_CASES=C14,C15,C16 npm --prefix tooling/e2e run test:real
```

保留源页面截图、副本每轮前后截图及几何数据。交互案例实际点击、输入并检查相应状态，滚动案例 C04 留存滚动到底部后的截图。交互失败会标为自动检查失败；布局和文案效果仍需逐项核对。采集仅用于本地评测，不向 Agent 反馈，不接入生产流程、不自动修复。

C14/C15 检查明确的内部/外部位置直接执行；C16 明确表达位置未确定、请求提供选择，然后根据实际返回的选项文本匹配外部下方选项，通过原生鼠标点击。断言澄清前 DOM/Revision 不变、点击请求带澄清 ID 和选项 ID、后续不重复澄清，并验证卡片内外关系、同栏位置、右侧区域坐标/宽度与表单交互。C16 证明指定选择流程可完成，不代表对任意含糊话语都能自行识别歧义。

页面仍是可控合成夹具，不包含真实站点框架、登录态、后台接口或业务数据。这里的“复杂”是相对于首批两个区块的页面，不等于生产复杂度已充分覆盖。

## 如何判定

报告中的 Playwright 通过表示自动断言通过，不等于完整语义验收。

- 所有案例检查请求有真实路由结果、记录到的任务没有失败或取消。
- 只问不改：检查版本号与页面 DOM 未变化；回答准确性仍需人工核对。
- 标题修改：检查目标文字实际可见，其他标题及两段正文保留；局部样式及其他细微变化仍需审核。
- 布局、颜色、技能内容等其余标准：当前主要保留浏览器与工具证据，人工依据 rubric 审核，不能因为流程结束就计作成功。
- 多轮用例连续使用同一副本、选区和对话；每轮单独留存证据。

每个结果的 `semanticReview` 初始都是 `pending`。需要核对问题、回答、工具行为及页面前后截图，明确标为通过、失败或无法判断后，才能统计语义成功率。澄清用例还应核对提问是否必要且抓住关键歧义。

## 证据

结果在 `output/real-model/runs/<run-id>/`，每次运行独立保存；首轮旧路径见《真实模型首轮评测结果》。与 `output/playwright/` 的确定性回归分开。

- HTML 测试报告和浏览器 trace。
- 每轮页面前后截图、最终 DOM 和元素几何/计算样式。
- 完整侧栏对话、真实路由结果、任务与工具日志、模型名称、耗时。
- `evaluation.json`：案例预期、自动检查、每轮证据及待人工审核状态。

超时或失败应先查看单个案例证据，区分网络、平台执行、意图理解和页面修改错误，再决定修复或重跑；不应通过自动反复重试掩盖不稳定。

### 真实页面小批次准备

使用 `node tooling/e2e/inventory-local-assets.mjs` 只读盘点当前工作区既有副本，清单写入已忽略的 `output/real-model/local-assets/inventory.json`，不复制正文、查询参数、会话或密钥，不发起网络请求。2026-10-01 盘点得到 36 份副本、32 个不同的起始 HTML；其中包含本地 Demo、外部站点账号页及行内业务页。数量不是可用或已脱敏资产数量。表单/弹窗节点可能隐藏，需实际渲染后才能确定素材适用性。

计划先选择三种真实页面，每种设置三类请求，共九项；当前仅为需求模板，待资产来源确定并检查页面后冻结实际文案、选区、澄清选项和验收锚点，不作为已执行案例：

| 页面类别 | 明确修改 | 含糊请求 | 后续调整 | 核心验收 |
| --- | --- | --- | --- | --- |
| 后台列表 | 调整一个已定位筛选项或列标题 | 目标不明时提出定位澄清 | 修改新增内容并保留前轮其余改动 | 表格、分页、其他筛选项保留，无错误位移 |
| 复杂表单 | 在明确分组中新增本地字段 | 分组或位置不明时确认范围 | 更改校验反馈，保留位置与原字段 | 分组与标签对应，交互反馈可见，无重叠/溢出 |
| 长页或弹窗 | 修改指定滚动区内的一块内容 | 对内外容器有实质歧义时确认 | 增加内容或改变尺寸 | 操作按钮可见/可达，内容可滚动，无裁切 |

来源选择待用户确认：当前本机真实模型连接外网；未审查的行内副本不能直接用于该模型调用。可选公开网页、先脱敏并确认结果的行内副本，或行内模型。公开域名也不代表账户页内容可公开，仍须排除账号信息。既有副本若用于测试，单独标为“真实页面副本编辑”，不将重新捕获副本冒充原网页捕获能力验证。此阶段没有运行真实模型批次或新增产品策略。

REAL_SUITE=demo npm --prefix tooling/e2e run test:real

| 案例 | 原页面 | 三轮请求 | 保留检查 |
| --- | --- | --- | --- |
| D01 | Demo 订单列表 | 新增负责人输入框 → 请求澄清按钮目标/改法 → 查询按钮改为搜索订单 | 表格全文逐轮一致，新增字段保留且可输入 |

### 桌面连续修改批次（2026-10-02）

D04–D06 固定 1440×1000 CSS 像素，计划 10 轮请求；D01 的窄屏诊断仍保留，按当前产品验收口径不作为阻塞项。

```sh
REAL_SUITE=demo REAL_CASES=D04,D05,D06 npm --prefix tooling/e2e run test:real
```

- D04：新增筛选字段 → 调整为两行 → 修改按钮名 → 删除新增字段并恢复单行。逐轮保留表格数据，检查横向位置、字段可输入及最终删除。
- D05：新增字段及本地验证按钮 → 必填和邮箱格式校验 → 改为选填。每轮规则修改后实际点击并验证空值、错误格式和合法邮箱，核对旧提示消失。只覆盖新增模块的本地验证，不宣称原有订单提交接口已接通。
- D06：复制任务卡片 → 只改副本 → 移动副本至任务 3 后。检查标题唯一及纵向位置顺序，保留原卡片、导航与固定提醒文本，最终滚动到底留图。

中途失败保留当轮证据并停止该案例后续请求，不靠重试凑通过。截图和自动断言分别记录；正常宽度下的样式、重叠及未覆盖区域仍需人工核对。

## 固定回归入口

在仓库根目录执行，测试工具仍独立安装在 `tooling/e2e`，不修改部署锁文件：

```sh
# 快速冒烟：默认模型（配置 ID 为 default）
npm --prefix tooling/e2e run test:smoke
# 同一冒烟使用 Qwen
npm --prefix tooling/e2e run test:smoke -- qwen
# 从相同初始页面比较默认模型与 Qwen
npm --prefix tooling/e2e run test:compare
# 核心回归：列表连续修改、表单校验迭代、卡片复制/移动
npm --prefix tooling/e2e run test:core
# 核心回归也可指定模型；会产生更多模型调用
npm --prefix tooling/e2e run test:core -- qwen
```

快速冒烟 D00 固定 1440×1000 视口，打开同一 Demo 订单页，通过正式插件进入新副本，选中查询按钮，发送相同要求改为“设置”。检查保存的 Revision、按钮可访问名称、原按钮 class/样式/位置和高度及非目标文字保持（文字变化引起的自然宽度变化允许）；刷新后再次确认文案与 Revision，验证保存结果。不是只检查接口成功。

`default` 代表本地配置的默认模型，不硬编码为 DeepSeek。其他参数对应 `model.alternatives[].id`。每次选择通过正式 model registry 创建路由、聊天和编辑适配器，保留协议、思考参数及密钥环境变量配置；测试隔离服务将其作为唯一默认选项。此入口验证指定模型的端到端编辑，不覆盖插件菜单切换和选择记忆。未知模型或缺失密钥会失败，不回退默认模型；不会改写用户的本地模型配置。

`test:compare` 顺序启动两个独立服务与浏览器副本，不在前一模型修改后的页面上测试下一模型，不自动重试。报告记录配置 ID、实际模型、协议/思考设置、页面资产和案例哈希、对话耗时、编辑阶段耗时、工具错误、Revision 和检查项。模型接口延迟与缓存状态可能不同，一次样本不能作为模型能力排名；报告自动通过仍需结合截图核对。

汇总写入 `output/real-model/regressions/<时间>/summary.md` 与 `summary.json`；原始证据仍在 `output/real-model/runs/<运行 ID>/`。任一运行失败或结果缺失，命令以非零状态退出。插件/服务相关修改后优先跑冒烟；Agent 策略、工具协议修改后及发版前跑核心回归。以上为真实模型浏览器 E2E，不新增或运行单元测试。
