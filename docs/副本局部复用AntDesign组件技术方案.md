# 副本局部复用 Ant Design 组件技术方案

> 状态：待评审，尚未实现。日期：2026-09-11。
> 本方案不将整页改成 React，不引入真实业务接口，也不要求行内安装 React 或 Ant Design npm 包。

## 1. 要解决什么问题

目前副本是 HTML、CSS 页面。新增下拉框有两种做法：原生 select 功能完整，但展开样式受浏览器控制；模型自建浮层可调整外观，却需要反复处理选中、关闭和键盘行为。

目标是让模型专注于“放在哪里、有哪些选项、默认选什么”，将下拉组件的标准交互交给真正的 Ant Design Select。

不承诺接入组件库就能解决所有问题：周边布局、容器容量、页面风格和模型规划耗时仍需要独立处理。

## 2. 当前项目事实

- 插件已依赖 `react ^19.1.0`、`react-dom ^19.1.0`、`antd ^6.0.0`，用于插件界面。首次实施应复用并核对锁文件实际版本，不借此升级依赖。
- 副本预览由服务端输出 HTML，目前 CSP 为 `script-src 'none'`、`connect-src 'none'`，禁止业务脚本和请求。
- 插件在静态副本中挂载受控交互运行时，处理自定义展开、复选和状态切换；它不是 Ant Design 运行时。
- 工作区文件目前是固定集合，包含 HTML、样式、结构索引等。增加组件配置必须贯穿版本保存、回退和备份，不能只增加一个预览脚本。

因此，这不是“引入 React 源码仓库”，而是增加一份使用 React、Ant Design 的浏览器运行产物，并建立组件配置与现有源码的关系。

## 3. 推荐架构：静态底板＋局部组件

```text
模型
  ├─ 现有源码工具：修改静态 HTML/CSS、决定外层布局
  └─ 组件工具：新增或修改经过校验的组件配置
                  ↓
工作区：index.html + author-overrides.css + components.json
                  ↓
服务端预览组装：注入受信任的组件启动入口和配置地址
                  ↓
浏览器：静态页面 + 局部 React 挂载点
                         ↓
                  Ant Design Select
```

React 官方支持在非 React 页面中通过多个 `createRoot` 挂载局部界面，无需接管整页。[官方说明](https://react.dev/reference/react-dom/client/createRoot)

### 谁负责什么

| 对象 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 静态 HTML/CSS | 原页面、组件外层位置、宽度和间距 | React 组件内部 DOM |
| 组件配置 | 选项、默认值、尺寸、允许的主题设置 | JavaScript、回调函数、任意 JSX |
| 组件运行产物 | 挂载、卸载、选择状态、官方组件交互 | 业务接口、文件上传、原系统操作 |
| 服务端 | 配置校验、版本管理、提供静态产物 | 执行 React、服务端渲染组件 |
| 插件 | 点选组件、对话、编辑进度 | 下载和执行服务器提供的远程扩展代码 |

## 4. 运行产物放在哪里

| 路径 | 优点 | 代价 |
| --- | --- | --- |
| 打包进插件，由插件挂载 | 可复用已有前端依赖，不必为页面开放脚本入口 | 组件修复需要更新插件；没有插件时不能挂载 |
| 独立浏览器产物，由服务端提供（推荐） | 组件版本可随服务部署；预览不依赖插件来渲染组件 | 必须设计预览 CSP、可信启动入口和产物版本管理 |

推荐第二种，避免进一步增加插件更新频率。它是服务页面自己的脚本，不通过扩展后台或 content script 动态执行远程代码。

交付过程：

1. 在行外构建环境安装 React、ReactDOM、Ant Design 及所需构建依赖。
2. 构建只包含已支持组件的 JS/CSS 产物，附带内容哈希、版本清单和许可证说明。
3. 将产物目录随服务交付包带入行内仓库和镜像，不依赖公网 CDN，不在行内重新打包组件库。
4. server 仅提供静态文件，不新增 React/Ant Design 运行依赖。

如果产物需要 ZIP，沿用现有“仓库保存目录、流水线打包”的交付习惯。构建产物包含第三方代码，仍需按行内规则确认登记要求，不能将“不执行 npm install”理解为不需要合规确认。

首版需要更新插件一次以识别组件选区；后续仅调整兼容的组件内部实现，原则上只更新服务端产物。配置协议或选区协议变化时仍可能需要更新插件。

## 5. 组件配置如何保存

以下是拟议协议，不是现有接口。

HTML 中只保存空挂载点，沿用系统生成的 sourceId：

```html
<div data-ui-source-id="source-200" data-ui-component-id="component-1"></div>
```

`components.json` 示例：

```json
{
  "schemaVersion": 1,
  "runtimeMajor": 1,
  "components": [
    {
      "id": "component-1",
      "hostSourceId": "source-200",
      "type": "select",
      "props": {
        "options": [
          { "value": "a", "label": "选项一" },
          { "value": "b", "label": "选项二" }
        ],
        "defaultValue": "a",
        "size": "middle",
        "disabled": false,
        "accessibleLabel": "选择来源"
      }
    }
  ]
}
```

- 配置使用严格字段白名单；拒绝未知类型、函数、脚本、HTML 标签字符串和任意 URL。标签作为纯文本渲染。
- 校验 ID 唯一、宿主存在、选项值不重复、默认值属于选项集合，并设置组件数和文本长度上限。
- 外层位置仍由模型结合实际页面决定，不固定上下或左右布局。
- 设计默认值与用户临时选择分开：修改配置形成 Revision；预览中选中其他项只是当前页面临时状态，刷新后恢复设计默认值。
- 首版不保存每次预览点击，也不联动真实“添加”业务；需要跨组件联动时另行设计声明式事件，禁止塞入回调代码。

## 6. 渲染与样式

### 6.1 挂载与卸载

启动脚本读取当前版本配置，对每个合法宿主创建 React root；重复启动不得重复挂载。配置变化时更新已有 root，宿主移除时卸载，释放监听器和弹层。组件异常要显示可理解的占位提示，不能让整个副本白屏。

没有组件的旧副本不加载运行产物。挂载点应保留合理尺寸，避免加载时大幅跳动。相同产物跨副本共享浏览器缓存，不把 React 复制到每个工作区。

### 6.2 样式隔离与主题

优先验证开放的 Shadow DOM：原页面管理宿主位置，组件内部样式放在 Shadow Root 中，减少原站全局 CSS 干扰。显式设置字体、字号等基础值；从页面获得的主题线索通过有限的主题配置传入，不导入整份原站 CSS。

Ant Design 官方文档提供 Shadow DOM 中使用 StyleProvider 指定样式注入容器的方式；实施时核对项目锁定版本及图标样式行为。[样式兼容说明](https://ant.design/docs/react/compatible-style/)

隔离不等于布局免疫：祖先的 overflow、transform、层叠上下文仍可能影响组件。不同网站的主题也不一定是 Ant Design 默认主题，不能硬编码某个站点的颜色或字号。

### 6.3 下拉弹层

显式配置弹层归属，不直接采用 `document.body` 默认位置。先验证组件 Shadow Root 内专用弹层容器，确保主题、定位和键盘行为一致。[ConfigProvider 文档](https://ant.design/components/config-provider/)

必须在滚动、裁切和定位容器中验证。若局部弹层被祖先裁切，再评估统一的页面级隔离弹层宿主及位置映射；不简单给所有祖先设置 `overflow:visible`，也不以无限提高 z-index 代替解决层叠问题。这是原型阶段的关键技术风险，尚不能保证仅配置一个参数即可解决。

## 7. 如何接入现有编辑工具

拟增加 `insert_component`、`update_component`、`inspect_component` 等通用工具：

- 插入时原子生成宿主和配置，sourceId 由系统分配，返回组件 ID、宿主 ID 和可编辑属性。
- 更新时只接受白名单属性；模型不操作组件内部 DOM，不需要知道 Ant Design 的内部 class。
- 检查时返回组件类型、配置和宿主布局上下文，不展开 React 的整棵渲染树。
- 现有移动、删除、克隆工具必须识别组件：删除同步删除配置；克隆生成新 ID 并复制配置；移动保留绑定。
- 所有工具包括通用文本替换和 patch，都在提交前检查宿主与配置的一致性，禁止意外清空配置或留下悬空引用。

静态部分仍使用现有工具，不把任意 HTML 自动替换为 React 组件。模型根据组件能力和用户要求选择原生控件或官方组件，不能仅按网站 URL 或业务关键词分支。

## 8. 插件点选、捕获和版本链路

### 点选

点击组件内部或弹层时，通过事件路径和组件归属信息映射到宿主 sourceId。编辑模式选中整个组件；普通交互模式保留 Select 的点击与键盘行为。弹层即使不在宿主 DOM 下，也必须映射到所属组件。

### 快照

重新捕获副本时，保存宿主和设计配置，不抓取 React 动态 DOM、CSS-in-JS style 标签或临时展开菜单。否则会重新出现源码膨胀、重复组件和无法继续编辑的问题。

### 版本与备份

`components.json` 加入工作区、候选版本、正式 Revision、撤销重做、克隆和批量导入导出的同一事务。旧副本缺少该文件时按空配置读取，无需批量迁移。

备份保存设计配置和运行时协议版本，不为每个副本重复打包组件库。不同环境导入时检查兼容性；不兼容要提示升级或保留占位，不能静默丢弃。单文件离线 HTML 导出首版不保证组件可运行，需在导出说明中明确。

## 9. 预览脚本与安全边界

不能把 `script-src 'none'` 简单改成允许所有脚本。

- 工作区仍禁止模型生成 script、事件属性和业务请求。
- 只有服务端预览组装器可以注入固定、版本化的可信启动脚本；使用响应级 nonce 或等效精确授权，禁止 eval 和任意内联脚本。
- 建议输出自包含产物，避免运行时动态加载任意 chunk；如需分包，提前限定资源清单。
- 配置从只读预览接口提供，绑定当前工作区、版本和预览授权，不把 token 写入日志或公共资源。
- 配置读取需要将 `connect-src` 从 none 调整为明确所需范围；组件代码不得提供任意网络请求能力。组件库不负责业务身份或原系统鉴权。
- `form-action 'none'`、禁止原站业务脚本等限制继续保留。预览授权不能成为公共静态资源的缓存键。

具体 nonce、配置接口和缓存方案需结合现有鉴权路由完成实现评审；此处不提前承诺“零安全改动”。

## 10. 实施范围与顺序

### 阶段一：验证运行方式，不接模型

用手工配置在静态副本挂载一个 Select，验证资源加载、样式隔离、弹层、选择、键盘操作和卸载。测量构建体积及首次加载耗时，确认行内产物交付可行。出现严重裁切或主题问题时先解决，不扩大组件范围。

### 阶段二：接入完整编辑闭环

接入组件工具、插件点选、配置保存、Revision 和备份；完成插入、修改选项、移动、克隆、删除、撤销重做及重新打开。

### 阶段三：真实需求验证

使用相同需求比较原生 Select 与官方 Select，记录结果、模型调用次数和总耗时。成功后再讨论 DatePicker 等复杂组件；不急于将所有 Button/Input 改为 React。

## 11. 验收与回退

按现有协作约定，不新增、不运行单元测试；实现时可做类型检查与打包，实际效果由用户验证。

人工验收至少覆盖普通文档流、flex、grid、定位容器和可滚动区域：

- 选中值与显示一致，键盘和焦点正常，菜单无明显裁切或错位。
- 点选能找到宿主，模型不改组件内部 DOM。
- 修改配置、撤销重做、刷新、导入后均恢复正确的设计状态。
- 没有组件的旧副本不受影响；脚本加载失败有明确提示。
- 不发起真实业务请求；源码中无法注入任意可执行代码。
- 记录与现有方案的加载体积、耗时和模型轮数差异，不提前认定能显著提速。

组件产物使用版本化路径和内容哈希，发布时保留兼容版本。回退服务时不能删除仍被副本引用的产物。不支持的组件保留配置并提示，不自动转换成外观不同的原生控件。

## 12. 评审结论建议

建议批准一个以 Select 为唯一首期组件的验证任务，而不是立即建设完整组件平台。

关键取舍是：接受一次组件运行层、配置协议和插件选区的改造成本，换取官方 Select 的标准交互和可维护样式；同时保持已有 HTML/CSS 页面及无组件副本不变。能否减少模型耗时需由同场景验证决定，不能用组件接入代替性能结论。
