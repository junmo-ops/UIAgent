# 副本对象存储部署说明

实现支持本地开发 `local` 和部署 `s3` 两种模式。S3 模式以远端对象为正式数据，本地目录是可重建缓存。插件无需填写任何存储参数。

## 配置

普通参数统一填写服务端的 `apps/agent-service/config/workspace-storage.json`。该文件随导出包和镜像提供，也可以由平台配置文件挂载覆盖，不需要为这些参数添加环境变量。修改后重启服务生效。

```json
{
  "mode": "s3",
  "cacheDirectory": "/opt/deployments/data/source-workspaces",
  "s3": {
    "endpoint": "https://你的存储端点",
    "region": "你的区域",
    "bucket": "你的私有桶",
    "prefix": "uiagent/production",
    "timeoutMs": 60000
  },
  "archive": {
    "bytes": 268435456,
    "compressedBytes": 67108864,
    "files": 20000
  }
}
```

仓库默认 `mode` 为 `local`，本地开发无需存储凭证。行内部署先迁移旧数据，再把 `mode` 改为 `s3`。相对 `cacheDirectory` 以服务包目录为基准，与启动命令的当前目录无关。配置文件缺失、格式错误或 S3 必填项缺失会拒绝启动，不静默回退本地模式。密钥字段不允许写入此文件。

**只有凭证通过环境变量／平台 Secret 注入：**

```dotenv
WORKSPACE_S3_ACCESS_KEY_ID=由Secret注入
WORKSPACE_S3_SECRET_ACCESS_KEY=由Secret注入
# 使用临时凭证时再提供，过期前须轮换并重启服务
# WORKSPACE_S3_SESSION_TOKEN=
```

原先方案中的 `WORKSPACE_STORAGE`、`WORKSPACE_S3_ENDPOINT` 等普通存储环境变量已取消，统一以配置文件为准。`SOURCE_WORKSPACE_DIR` 的兼容覆盖也已移除，所有存储模式均使用文件中的 `cacheDirectory`。普通服务参数迁移详见《服务配置说明》。

保留现有 `INSTALLATION_TOKEN_SECRET`；租户和鉴权参数迁至 `service.json` 时保持原值。密钥变化可能导致原安装身份无法访问数据。证书链由平台配置；公司 CA 可通过 `NODE_EXTRA_CA_CERTS` 指定。

权限包括专用前缀的 GetObject、PutObject、DeleteObject、ListBucket，以及桶级 GetBucketVersioning。工作区对象位于 `<prefix>/v1/workspaces/`，初始化权限探针位于 `<prefix>/v1/probes/`，授权需覆盖二者。探针不包含用户数据；异常退出留下的探针可由平台按短期生命周期清理，生命周期规则不能套用到工作区对象。

**第一版要求从未启用版本控制的桶**。启用或曾启用后暂停版本控制的桶都会拒绝启动，以避免普通 DELETE 后历史对象仍保留、与永久删除语义冲突。若现有 COS 不支持查询桶版本策略，需要先适配并验证该产品能力，不能跳过检查。不得在独立前缀上并行运行迁移工具或其他写入程序。

必须单实例、单 Node 进程运行，发布使用先停旧实例再启新实例的方式。不同环境使用不同桶或前缀。仅配置副本存储不会持久化独立运行日志；日志请接入平台日志服务。

## 迁移旧数据

先完整备份旧 `source-workspaces` 目录，然后停写、结束或取消任务，取得最终备份。不要只使用插件的当前快照导出。

以下命令从部署工程根目录执行，迁移命令自动读取同一份存储配置文件；密钥变量由平台或当前进程注入，不会自动加载 `.env` 文件。

```bash
# 仅检查本地备份，不写对象存储，不删除源数据
pnpm --filter @ui-agent/agent-service storage:migrate --source /backup/source-workspaces --report /backup/preflight.json

# 停止原服务、配置 S3 参数后执行上传与回读校验
pnpm --filter @ui-agent/agent-service storage:migrate --source /backup/source-workspaces --apply --report /backup/migration.json
```

迁移保留 ID、归属、源码、历史、会话及任务记录。相同 ID 且文件内容一致可跳过续跑；内容不一致则停止，禁止覆盖远端。源目录有不识别条目、缺失历史或校验错误时停止，不静默跳过。迁移报告存放在源目录之外，不包含源码和凭证。

预检查与正式上传均使用配置文件中的容量限制。若需调低或调高限制，应在实际上传前核对报告中的大小和文件数。上传期间不要改动备份或启动服务。

迁移完成后，使用**空缓存目录**启动 S3 服务。程序拒绝把未标记的非空旧数据目录当成缓存清理。不要把旧备份直接作为 `cacheDirectory` 启动；备份保留在独立位置。

## 启动和发布

- `/live`：进程存活探针，恢复期间也可响应。
- `/ready`：初始化完成且不存在提交结果未确认的副本时返回 200，否则 503。
- `/health`：保留服务能力信息；初始化期间返回 503。

启动时检查桶策略、读写删除权限，分页列举并完整恢复所有副本，校验成功后才开放业务。不能将远端错误解释成空列表，也不会从残留本地缓存重新上传数据。缓存标记绑定存储地址、桶和前缀，更换这些参数需使用新空目录。

部署平台需设置足够的启动等待时间，并避免使用 `/health` 作为会在恢复期间不断杀进程的存活探针。服务收到停止信号后拒绝新请求，为在途 S3 写入／模型任务提供最多 30 秒退出窗口；超时中断的任务在下次启动后显示已中断，不自动重跑。平台终止宽限期应大于此窗口。

启用后用原身份打开副本、查看对话和历史、继续修改并撤销／重做，再进行一次真实重新部署。确认通过后才完成切换。

## 保存失败与恢复

远端确认前，只提供上次确认版本；任务显示保存中。明确拒绝写入时返回错误，原版本保留。

上传超时可能已经写入，因此会读取 commitId 核对。无法确定提交结果或远端成功后缓存切换失败时，该副本暂停访问，列表与就绪探针也返回不可用，避免展示错误数据。当前实现不自动重放未确认操作。由管理员排查连接、等待旧请求结束，停止旧实例后重新启动，从远端权威对象恢复。不要用新的 turnId 重新执行模型来验证是否已保存。

任务终态无法持久化时，当前进程可报告“结果未持久化”；重启后根据远端接受记录显示已中断。源码、Agent 对话上下文和任务结果同一次提交；插件原有展示消息追加仍使用对话保存接口。

## 容量和性能

默认每份副本：原始文件合计最多 256 MiB，压缩对象最多 64 MiB，最多 20,000 个文件；可在配置文件的 `archive.bytes`、`archive.compressedBytes`、`archive.files` 调整。请求超时在 `s3.timeoutMs` 中设置，默认 60 秒。

这些是保护上限，不代表性能承诺。每次保存（含任务接受、对话更新）都上传完整副本；启动恢复全部副本。压缩和文件复制也需要内存、CPU、临时磁盘，应按真实数据测量保存和恢复耗时。反向代理与客户端请求超时需留出上传时间；客户端超时不等于远端未保存。

需要为已恢复数据、并发修改的暂存目录和新启动恢复预留磁盘。容量超限会拒绝保存，不自动截断历史。所有副本总量过大时需另做按需恢复与增量对象设计。

## 回退和验收边界

S3 启用后的版本回退仍须支持该归档格式，不能让旧版服务直接使用过期本地目录。如必须恢复旧存储模式，需要停写、导出最新完整远端数据并验证，不能直接改为 `local`。

按工程约定不新增、不运行单元测试。类型检查、构建及锁文件检查不能替代真实 COS 验收；需在行内验证断网、权限拒绝、任务中断、空缓存恢复、删除后不复活与用户隔离。当前尚未提供行内凭证，因此这些场景不能声明已验证。

## ZIP 归档与格式切换

副本对象现在为 `<prefix>/v1/workspaces/<workspaceId>.zip`，Content-Type 为 `application/zip`。Windows 可使用“全部解压缩”或 7-Zip；解压后直接查看 index.html、样式、module.jsx、workspace.json、revisions 和 turns 等文件。workspace.json 包含会话与对话记录。

归档内的 `__uiagent_archive__.json` 保存提交标识和文件哈希，服务用于校验完整性；该文件不写入本地工作区，源码也不再使用 Base64 编码。不要直接编辑 COS 中的 ZIP；手工修改后哈希可能不匹配。

按用户要求，不读取、不自动转换旧 `.json.gz`。启用 ZIP 版本前停写，先独立备份旧数据；将旧归档移出所用的 `v1/workspaces/` 前缀，或为 ZIP 配置新的 prefix 和空缓存目录。旧对象仍混在同一工作区前缀时，初始化会报出无法识别的副本对象，不会默默跳过。程序不会替你删除 COS 数据。

若需保留旧副本，可在升级前从旧版本取得完整本地工作区目录备份，再用 storage:migrate 命令上传为 ZIP；该命令接收目录，不接收旧 gzip 对象。更换前缀并直接启动空环境不会自动出现旧副本。

依赖固定为 fflate@0.8.3，行内可用性已由用户查询确认；其他依赖版本保持不变。单份归档业务文件最多 65,534 个（另有 1 个元数据文件），实际还受 archive.files 限制，默认 20,000 个。
