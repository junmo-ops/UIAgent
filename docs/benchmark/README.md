# UIAgent 手工 benchmark v1

状态：已建立用例与固定合成资产，**尚未执行产品效果评估，尚无通过率基线**。这不是单元测试，也不接入线上 Agent 的自动验证/修正流程。

## 从这里开始

1. 在项目根目录运行 `pnpm --filter @ui-agent/demo-page dev`，打开终端提示的地址（默认 http://127.0.0.1:5173/benchmark/）。不要用 file:// 打开。
2. 插件和 Agent Service 按主 README 启动；先确认它们指向同一个测试环境。不得为跑 benchmark 升级依赖。
3. 复制 [批次模板](templates/batch.md) 到自行创建的结果目录，填写代码版本、插件版本、模型配置和视口。复制 [单次记录模板](templates/run.md)，每次尝试独立记录。
4. 按 [30 个场景](cases.md) 执行。初次先跑 C01、C02、C03、E01、E03、E07、E08、L01；它们只是快速检查，不代表完整覆盖。
5. 固定页面只提供起点，不含目标实现。只给模型“提示词”段和明确的选区，不提供验收答案、CSS 选择器或本文件。
6. 第一轮完整运行后，保留这一批结果；以后在相同资产、提示词、配置下与它比较，不能覆盖失败记录。

## 资产

四个固定页面在 `apps/demo-page/public/benchmark/`，使用现有 demo 的静态资源服务，不修改原 demo，不引入服务或依赖。

| 编号 | 页面 | 用来覆盖什么 |
| --- | --- | --- |
| F1 | flow.html | 普通文档流、长内容、表单初值、原生 details |
| F2 | flex.html | Flex 换行、工具栏、表格、禁用按钮、CSS 变量、@import、外部 SVG、伪元素、明暗主题 |
| F3 | grid.html | Grid 跨列、嵌套 Flex、侧边导航、不同内容长度、响应式 |
| F4 | layers.html | 根节点禁止滚动、子容器滚动、sticky、absolute 标记、fixed 浮层 |
| R1 / R2 | 待登记 | 两种不同机制的、已获授权并脱敏的真实页面；见 [真实资产登记](real-assets.md) |

数据固定且虚构，无外部 CDN、时间随机值或业务请求。按钮多数只是原站展示；**原站脚本交互不在副本原样复用的承诺内**。F2 主题切换脚本仅用于设定采集前状态；验收的是采集时外观，不要求副本继续运行此脚本。固定系统字体，不将字体文件捕获算作已覆盖。

这些资产属于开发集，不是真实生产样本。Shadow DOM、跨域 iframe、虚拟列表、Canvas/WebGL、远程字体、复杂权限及超大页面仍是覆盖缺口；不得据此声称任意网页可用。

## 统一起点

- 使用专用测试 Chrome Profile、虚构数据及测试实例。导出、删除、并发和重启不作用于日常工作副本或生产环境。
- 每个独立任务：重新加载固定原页 → 创建新副本 → 新会话 → 按用例选区。**不要用“恢复初始”当作清空会话**，它目前只恢复页面。
- 单轮任务只发原文。多轮任务按指定顺序发送，不额外引导；需要人为纠错时另记为“救援轮次”，不能算首次通过。
- 默认原页面内容区 1440×900 CSS 像素、缩放 100%、浅色、根和子容器滚动位置为 0；例外写在用例中。记录实际 innerWidth/innerHeight、DPR、浏览器版本和侧栏宽度，不用显示器分辨率替代。
- 捕获任务：等样式和图片就绪，记录**捕获时实际内容视口**。对照截图时关闭 F12，原页与副本的侧栏开关、视口、主题和滚动位置保持一致；不要把视口差异当成还原失败。另存采集前/副本截图及采集状态。
- 编辑任务：先确认初始副本质量；初始副本不合格则登记 capture 失败，编辑标记 blocked，不把捕获问题归到模型编辑。
- 每个任务保存浏览器真实截图/录屏与日志引用。副本存储 ID、conversationId、turnId 都要对应当前尝试；不跨用例复用有上下文污染的会话。
- 模型的合理澄清不自动算失败。按用例指定答复回答；额外的非预设信息须记录，不允许暗中给答案。

## 验收与评分

所有编辑任务的公共不变量：
1. 完成用户可见的目标；不要求固定 DOM、源码、组件层级或工具顺序。
2. 没有无关区域的内容丢失或意外样式改动。
3. 在任务指定尺寸下可见、可操作，没有新增的意外重叠、裁切或根级横向溢出；F2 表格内部横向滚动不自动算失败。
4. 新增交互只使用本地演示数据，不向真实业务系统提交。
5. 正式保存后刷新仍存在；不要求保留组件内未提交的临时输入。
6. 声称使用 Ant Design 时，除外观外检查模块导入和渲染证据，不能只相信模型总结。

状态只选一个：
- pass：所有必需项通过，证据完整；允许用例预设的多轮/澄清。
- partial：主体目标达到，但有次要验收项未满足。不是通过。
- fail：目标未达成、关键交互错误或破坏不变量。
- blocked：缺资产、环境不可用或前置捕获失败。写清阻碍，不能记 pass。
- not-run：未执行。不是 fail，也不能默认为 pass。

另记失败层：capture / intent / edit / interaction / persistence / tab-binding / isolation / infrastructure。原因未知时写 unknown，不靠猜测归因。

两种分母都报告：**覆盖率 = 已执行(pass+partial+fail) / 计划任务数**；**首次通过率 = 首次 pass / 已执行数**。同时公开 blocked 和 not-run 数量。重复尝试的成功率另外报告，禁止取“最好一次”。层级结果分开看，不合成为一个总分。

## 速度、成本和稳定性

- 人工端到端时间：点击发送至最终回答且保存状态明确。捕获时间单独计。
- 服务器执行时间：日志 durationMs；不能当作端到端耗时。
- SDK 调用、工具尝试/失败/拦截、Token 用量按 [日志说明](../Agent日志排查说明.md) 提取，缺失记 N/A，不能补零。
- 路由、编辑可能对应不同日志，保存全部引用。usage 按实际可辨识的调用加总，区分输入、输出、缓存；字段口径不明不合计，不重复累加聚合值。
- 只有确定对应日期、模型及缓存计费规则时才计算金额。否则只记录 Token。
- 每个任务同时记录预设对话轮次、模型澄清次数、额外救援轮次；“补了三次说明才成功”不能等价于首次完成。
- 第一轮所有可执行任务跑 1 次。阶段比较时对 E05、E07、E08、E11、E12 各独立重复 3 次；对照版本同样重复，相同环境交错运行，保留全部失败。
- 小样本报告原始值与中位数即可，不用不可靠的 P95 包装稳定性。先收基线，之后再商定速度预算，不预设一个伪精确达标数。

## 发布决策与保留集

安全/数据阻断项：误操作其他 Tab、跨用户泄露、已确认保存的数据丢失、意外执行真实业务请求。任一出现，阻断该版本上线并调查；没有实际验证的隔离项不能宣称安全通过。

效果问题可形成已知能力边界，限制内部试点范围。但不能因为简单文案任务通过，就忽略复杂结构任务的回退。

本仓库的固定页面和全部公开提示词都是**开发回归集，不具备盲测保密性**。R1/R2 由评估负责人在内部单独持有，冻结采集资产和最终提示词后再做阶段验收；当前还没有真正的私有保留集。保留集问题被用于开发后，应转入回归集并补充新样本。

遇到失败先解释可泛化的机制，再在另一种布局验证。禁止在产品中根据本集 ID、文案、URL 或 class 增加分支，也不能为了提高分数修改任务答案。
