# 技能接入与脚本执行

第一版支持团队审查并随服务发布的技能包、按需参考文件、Node.js `.mjs` 和 Python `.py` 脚本。插件右侧工具栏的“技能”打开与历史会话一致的管理面板，支持搜索和逐项开关，不提供删除。默认全部开启，模型从开启的技能中按需选择；单轮仍固定一个主技能，并非同时执行全部技能。

开关按服务地址、租户和用户 ID 保存在当前浏览器的插件存储中，刷新、新建会话和重开侧栏后保留，同一浏览器的侧栏同步设置；不跨浏览器或设备同步。新增技能默认开启。每轮发送时固定关闭列表，经路由传到问答和编辑 Agent；服务端过滤目录并拒绝加载关闭技能，设置变化对下一轮生效。全部关闭仍可正常聊天和编辑。

## 发布一个技能

在 `apps/agent-service/skills/<id>/` 放入：

```text
skill.json
SKILL.md
references/      # 可选参考文档
assets/          # 可选文本模板
scripts/         # 可选脚本
```

`SKILL.md` 可以沿用 Agent Skills 的 YAML frontmatter + Markdown 格式。当前版本不解析通用 YAML；服务发布目录的索引和脚本白名单以 `skill.json` 为准。外部 skill 必须经过审查、补齐清单并适配工具名称后发布，不是任意目录即插即用。

```json
{
  "id": "my-skill",
  "displayName": "我的技能",
  "description": "说明用途以及何时使用",
  "scripts": [
    { "path": "scripts/run.py", "runtime": "python" },
    { "path": "scripts/run.mjs", "runtime": "node" }
  ]
}
```

目录名与 ID 一致，正文中的名称、描述也应与清单一致。每包不超过 100 个文件、2 MiB；SKILL.md 不超过 24000 字节，单次参考文件读取不超过 32000 字节。不支持符号链接。错误的包会被禁用并记录启动日志，其他技能仍可使用。

服务启动时读取技能文件并计算 SHA-256 内容版本。任务和脚本使用内存快照，不会在执行中读取后来被改写的技能源码。部署新版本后旧版本请求会提示重新发送，不会静默换用新脚本。第一版修改技能需要重新发布服务；普通技能内容变更不需要重新发布插件。服务离线导出会包含 skills 和配置目录。

## 脚本协议

`displayName` 是可选的界面显示名称，最长 40 字符，未提供时显示技能 ID。技能面板展示名称、用途和开关；输入区不再提供技能选择器或已选标签。

模型通过 `run_skill_script` 提供 `script`、JSON 对象 `args` 和 `inputs: [{path,text}]`。只有清单中声明的脚本能执行，不接受 Shell 命令字符串，也不会自动安装依赖。

脚本从标准输入读取一个 UTF-8 JSON 对象：

```json
{
  "args": {"title": "需求说明"},
  "inputDir": "本次输入文件目录",
  "outputDir": "本次产物目录",
  "skillDir": "本次技能包快照目录"
}
```

- Node.js 使用服务端 Node 解释器，文件扩展名 `.mjs`。
- Python 使用配置的解释器，以 `-I -B` 启动。内置脚本兼容 Python 3.7.9，只依赖标准库。
- 输入文件、技能快照与正式副本分开；工作目录为本次新建的临时目录。脚本不自动获得页面文件，Agent 必须明确提供所需输入。
- 成功时收集 outputDir 内的 UTF-8 文本文件，返回 `{path,text}`、退出码、stdout/stderr、技能版本。失败时不返回候选产物。二进制文件下载和长期产物保存尚未提供；不要输出虚构下载链接。
- 文本产物随工具结果交回 Agent；需要改变页面时由现有源码工具应用，并走既有校验和提交流程。脚本运行成功不代表页面修改成功或渲染验证通过。
- 正常退出、失败、超时和取消后均清理临时目录。服务被强制杀死可能留下临时目录，应使用平台的临时目录配额和生命周期管理。

## 配置与部署

普通配置在 `apps/agent-service/config/skills.json`，没有新增环境变量和 npm 依赖。

| 字段 | 用途 |
| --- | --- |
| directory | 相对于服务目录的技能根目录 |
| pythonExecutable | 默认 python3，可填写部署容器内的绝对路径 |
| timeoutMs | 单次脚本最长运行时间，默认 30 秒 |
| maxConcurrentScripts | 服务进程内脚本并发，默认 2 |
| maxRunsPerTurn | 单轮脚本调用次数，默认 3 |
| maxInputBytes | args 和 inputs 的合计 JSON 字节预算 |
| maxOutputBytes | stdout/stderr 合计上限，以及成功后产物合计上限（分别计算） |
| maxFiles | 成功后产物文件数上限 |

在实际部署容器确认环境：

```sh
command -v python3
python3 --version
cd /opt/deployments/apps/agent-service
pnpm skills:check
```

检查命令只检查配置、技能目录和解释器，不调用模型、不执行技能脚本。Python 不可用时 Python 脚本显示 available=false，Node.js 和服务启动不受影响。若命令为 python，修改 pythonExecutable 即可。当前 Dockerfile 不自动安装或升级 Python；部署镜像由平台提供。内置脚本无 pip 依赖，新增依赖需要先确认行内源与 Python 3.7.9 的兼容版本，再固定安装到执行解释器的环境中。

## 执行边界

这是可信脚本子进程执行器，不是安全沙箱。不会继承 MODEL_API_KEY、S3 Secret、NODE_OPTIONS 等服务环境变量，但脚本仍拥有服务进程对应操作系统用户的文件和网络权限。只读文件模式、独立 cwd 和不传正式副本路径都不能防御恶意脚本，尤其不能在 root 服务中依赖这些作为权限隔离。

当前实现限制并发、执行时间和捕获的输出；Node.js 设置 128 MiB 堆上限。这不是进程总内存、CPU 或磁盘配额，Python 也没有独立内存硬限额。部署时使用容器资源限制；未提供用户上传或外部技能在线安装入口。若要执行不可信脚本，必须先增加独立容器/沙箱以及网络、文件和资源隔离。

Linux/macOS 使用进程组终止子进程及其后代，支持用户停止任务和聊天连接断开；Windows 当前只终止直接子进程，不作为脚本执行服务的部署目标。代码不会授予新工具权限，技能说明和脚本输出不能覆盖平台规则。

## 验证场景

### 本机与行内配置分离

非 production 启动时，服务优先读取 `config/service.local.json`、`config/workspace-storage.local.json` 等同名本地文件；它们是完整配置，不是局部覆盖。没有本地文件时读取正式 JSON。`NODE_ENV=production` 忽略本地文件。本地配置、`.local-workspaces` 不进入 Git、Docker 构建上下文或服务导出包。

本地 service 配置使用 `auth.mode=development`、`http.publicBaseUrl=http://127.0.0.1:8787`；存储配置使用 `mode=local` 和独立的 `cacheDirectory=.local-workspaces`。模型地址仍需指向本机能够访问的服务，模型密钥由本地 `.env` 提供。

在项目根目录启动服务：

```sh
NODE_ENV=development pnpm dev:service
```

单独构建连接本机的插件，避免覆盖行内发布目录：

```sh
cd apps/extension
WXT_PUBLIC_AGENT_SERVICE_URL=http://127.0.0.1:8787 pnpm exec wxt build --browser chrome
```

Chrome 加载或重新加载 `apps/extension/.output/chrome-mv3`。插件服务地址以本次构建为准，会更新旧构建缓存的服务地址。正式发布仍使用原有 build/release 脚本，默认指向行内服务。

### 技能执行验证

快速验证可在技能面板确认 `skill-runtime-check` 已开启，发送：

> 验证 Python 技能执行链路，验证文本是“你好，UIAgent”。请实际调用脚本并展示执行报告。

应返回实际 Python 版本、UTC 执行时间、随机执行 ID、原文、字符数、UTF-8 字节数和 SHA-256。相同文本再次运行，随机执行 ID 应不同，计数及哈希应相同；同时核对服务端 `[skill-script]` 日志中的 `skillId=skill-runtime-check`、`script=scripts/report.py` 和 `exitCode=0`。该技能不修改页面，不需要选中模块。模型自己生成一段类似报告不算通过，应同时有脚本执行日志。

按工程约定不新增、不运行单元测试。真实环境请验证：

1. 开启 requirements-outline，在消息中要求使用该技能整理几个需求点，确认 Python 产物进入回答；服务日志出现 `[skill-script]` 的版本、退出码和耗时。
2. 明确要求使用该技能的 Node.js 脚本，确认等价文本输出。
3. 自动模式下分别提出页面修改、需求整理和普通问答，观察是否选择合适的技能。
4. 开启 ui-consistency，基于不同布局形态的页面修改，确认仍经过原有意图、源码校验及提交流程。
5. 执行期间停止任务，核对进程结束、工作目录清理、正式副本无绕过提交的修改。
6. 缺少 Python、脚本非零退出、超时或超出输出上限时，应如实返回失败，不能声称产物成功。
7. 关闭技能后，即使消息要求使用该技能，也不应出现其脚本执行记录；全部关闭后普通问答、页面修改仍可用。刷新、新建会话及重开侧栏后检查开关保持不变。

修改类任务和普通问答的技能工具调用均进入现有运行日志。问答日志模式显示为“问答 / 技能”，详情中“技能工具调用”记录调用参数、返回内容（单次最多保留 16000 字符）和错误；“运行诊断”记录模型调用及工具状态。日志在本轮结束、失败或取消后写入，沿用现有管理员权限和脱敏规则。服务终端同时保留脚本执行摘要。类型检查与构建通过不能替代模型选择、Python 3.7.9 容器运行和页面效果验证。
