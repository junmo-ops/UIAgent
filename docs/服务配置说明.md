# 服务配置说明

服务配置现在分为两份文件，均位于 `apps/agent-service/config/`：

- `service.json`：模型、鉴权、对外地址、CORS、日志和诊断。
- `workspace-storage.json`：副本存储模式、缓存目录、S3 普通参数和容量限制。

文件随导出工程、Docker 镜像提供，也可挂载覆盖。路径以服务包为基准，不依赖启动时的工作目录。修改后重启服务生效。文件使用严格字段校验，未知字段和密钥字段均不接受，文件缺失或格式错误拒绝启动。导出直接复制配置，不重新生成业务参数。

## 保留的环境变量

| 变量 | 用途 |
| --- | --- |
| `MODEL_API_KEY` | 模型调用密钥，正式运行必填 |
| `INSTALLATION_ADMIN_USER_IDS` | installation 管理员用户 ID，英文逗号分隔；空值表示无管理员，修改后重启生效 |
| `INSTALLATION_TOKEN_SECRET` | installation 身份签名密钥，至少 32 字符，需保持稳定 |
| `WORKSPACE_S3_ACCESS_KEY_ID`、`WORKSPACE_S3_SECRET_ACCESS_KEY` | S3 模式凭证 |
| `WORKSPACE_S3_SESSION_TOKEN` | 使用临时 S3 凭证时填写 |
| `HOST`、`PORT` | 平台监听配置，镜像默认 0.0.0.0:8787 |
| `NODE_ENV` | 运行环境，Dockerfile 设置 production |
| `NODE_EXTRA_CA_CERTS` | Node 企业 CA 配置，按需设置 |

`PNPM_HOME`、`PATH` 由镜像管理，无需额外填写。常规“模型 + installation 身份 + S3”部署需要 4 个凭证变量，临时 S3 凭证时再增加 1 个。

插件构建地址 `WXT_PUBLIC_AGENT_SERVICE_URL`、发布说明 `EXTENSION_RELEASE_NOTES`、依赖预检源 `INTERNAL_NPM_REGISTRY` 是独立构建工具的输入，不属于服务运行环境。此轮没有更改插件构建流程。

## service.json 字段

| 配置字段 | 含义／仓库默认 |
| --- | --- |
| `model.baseUrl` | 模型接口地址，默认 https://api.deepseek.com |
| `model.name` | 模型名称，默认 deepseek-v4-flash |
| `model.providerLabel` | 日志和健康信息展示名称；不改变调用协议 |
| `model.edit.maxIterations` | 源码修改迭代上限，45 |
| `model.edit.maxOutputTokens` | 单次源码修改模型输出上限，8192 |
| `model.router.maxIterations` | 助手意图路由迭代上限，3；允许 1～5 |
| `auth.mode` | auto、installation、development 或 external |
| `auth.installation.tenantId` | 租户，internal-pilot；迁移时保持线上原值 |
| `auth.installation.tokenTtlSeconds` | 安装令牌有效期，31536000 秒 |
| `auth.installation.previewTokenTtlSeconds` | 预览令牌有效期，604800 秒 |
| `auth.development.userId` / `tenantId` | 仅开发身份使用，默认 local-developer / local |
| `http.publicBaseUrl` | 网关对外根地址；空字符串表示根据请求地址生成 |
| `http.corsOrigin` | 空字符串沿用未指定 CORS 的原有行为；也可填写 * 或具体 Origin |
| `logging.file` | 默认 .logs/agent-turns.jsonl，相对服务包目录；可填写绝对路径 |
| `diagnostics.replicaAEnabled` | 冻结计算样式诊断变体，默认 false |

`auth.mode=auto` 在 NODE_ENV=production 时选择 installation，其他环境选择 development。生产环境选择 development 仍会拒绝鉴权，没有绕过开关。external 启用行内登录，需要完整的 auth.sso 配置和 SSO_PRIVATE_KEY；联调前保持 installation（部署）或 development（本地）。

源码服务固定使用远程模型，不再要求 MODEL_MODE；副本身份隔离固定开启，不再提供关闭开关。

## 可选模型与本地 Qwen / Kimi

默认模型仍由 `model.baseUrl/name/providerLabel` 和 `MODEL_API_KEY` 配置，插件默认选中它。可在 `model` 内添加 `alternatives`：

```json
"alternatives": [{
  "id": "qwen",
  "label": "Qwen 3.8 Max",
  "baseUrl": "https://maas.qianwenaiapi.com/compatible-mode/v1",
  "name": "qwen3.8-max",
  "providerLabel": "qwen",
  "apiKeyEnv": "DASHSCOPE_API_KEY",
  "enableThinking": true
}, {
  "id": "kimi",
  "label": "Kimi K3",
  "baseUrl": "https://api.moonshot.cn/v1",
  "name": "kimi-k3",
  "providerLabel": "kimi",
  "apiKeyEnv": "MOONSHOT_API_KEY"

}]
```

Qwen 地址来自本次用户控制台的 Chat Completions 示例，应与实际账号和密钥匹配；Kimi 地址及模型 ID 依据 [Kimi Chat Completions 文档](https://platform.kimi.com/docs/api/chat)。本地将配置加到 `config/service.local.json` 的 `model` 中（该文件为完整配置覆盖，不是局部合并），在 `.env` 分别添加 `DASHSCOPE_API_KEY` 和 `MOONSHOT_API_KEY`，重启服务并重新打开侧栏。只试用其中一个模型时，仅配置对应密钥即可。不要将密钥写入 JSON 或插件。未配置密钥的可选模型显示“未就绪”，不影响默认模型。

Kimi K3 始终开启推理，本配置不发送 Qwen 的 `enable_thinking`，也不覆盖 Kimi 的默认推理强度（文档默认 `max`）。工具循环沿用现有 SDK 的 reasoning 消息回传能力，不把日志中截断的推理文本用作模型上下文。模型可选择仅代表密钥已配置，不代表接口、余额或模型权限已验证；需要实际验证普通聊天、页面读取及多轮工具编辑。推理耗时与输出预算是否适合当前任务也需通过真实日志观察。

插件记住当前用户在当前服务下的选择；执行中禁止切换，一次发送的路由、聊天及后续编辑沿用发送时的模型 ID。切换从下一轮生效，不清空会话、不回退副本。不可用的模型明确报错，不静默回退。日志的 `model` 记录实际配置的提供方和模型名称。

`apiProtocol` 可选，目前仅支持 `chat-completions`。`enableThinking` 指定时透传为请求体 `enable_thinking`。所有模型复用现有 Agent 工具和编辑额度，不启用供应商的内置联网或代码执行工具。

线上 `NODE_ENV=production` 不读取 `.local.json`。本轮不改线上模型；后续在正式配置添加对应内部接口及独立密钥环境变量即可，内部接口的工具调用兼容性仍需单独验证。

## 从旧环境变量迁移

管理员名单按用户要求继续使用 `INSTALLATION_ADMIN_USER_IDS` 环境变量，不放入 service.json；若曾手工添加 `auth.installation.adminUserIds`，请将内容改为逗号分隔的环境变量并删除该文件字段。

不能先删除平台配置再使用样例默认值启动。请先把线上实际值填入配置文件，然后删除旧变量并部署。服务不检测或提示旧环境变量，普通参数仅从配置文件读取。配置文件仍需包含正确的部署值，格式错误或缺失仍拒绝启动。

| 旧变量 | 新字段／处理方式 |
| --- | --- |
| MODEL_BASE_URL / MODEL_NAME / MODEL_PROVIDER | model.baseUrl / model.name / model.providerLabel |
| CLINE_MAX_ITERATIONS / CLINE_MAX_OUTPUT_TOKENS | model.edit.maxIterations / maxOutputTokens |
| MODEL_MAX_ITERATIONS | model.router.maxIterations；明确设置 1～5 |
| AUTH_MODE | auth.mode；旧 required 使用 external，已有 installation 保持 installation |
| INSTALLATION_TENANT_ID | auth.installation.tenantId |
| INSTALLATION_TOKEN_TTL_SECONDS / PREVIEW_TOKEN_TTL_SECONDS | auth.installation.tokenTtlSeconds / previewTokenTtlSeconds |
| DEV_AUTH_USER_ID / DEV_AUTH_TENANT_ID | auth.development.userId / tenantId |
| PUBLIC_BASE_URL / CORS_ORIGIN | http.publicBaseUrl / corsOrigin |
| LOG_FILE / REPLICA_A_ENABLED | logging.file / diagnostics.replicaAEnabled |
| SOURCE_WORKSPACE_DIR | workspace-storage.json 的 cacheDirectory |
| MODEL_MODE | 删除，正式运行固定 remote |
| WORKSPACE_IDENTITY_ISOLATION | 删除，身份隔离固定开启 |
| ALLOW_INSECURE_DEV_AUTH | 删除，生产禁止开发身份 |

S3 普通参数同样只从 workspace-storage.json 读取，见[对象存储部署说明](副本对象存储部署说明.md)。存储迁移命令只依赖存储配置文件与存储凭证。

特别核对租户、签名密钥、管理员列表、对外地址、日志路径和缓存目录。原镜像把日志放在 `/opt/deployments/data/logs/agent-turns.jsonl`；如果继续沿用该目录，请在 logging.file 明确填写该绝对路径。没有日志环境变量替你覆盖配置文件了。

本次没有读取平台真实配置，无法替你自动填入这些线上值。也没有改动插件协议或升级依赖。

### 模型工具参数兼容诊断

`2026-10-02-tool-validation-v18` 将交互计划 Schema 显式声明为对象，同时保留不同 mode 的条件校验；不把字符串自动转换为对象，也不绕过写入前的意图声明。参数校验错误会列出 Schema 中的字段名及实际类型（例如 `interactionPlan=string` 或 `missing`），不记录参数值。此项用于定位模型/网关工具参数兼容问题，不代表已验证所有模型。

同一轮执行中，同一工具连续三次返回完全相同的本地 `ToolInputValidationError` 时，以 `TOOL_INPUT_VALIDATION_STALLED` 结束；该工具成功或返回其他错误后重置计数，其他读取工具不重置其计数。终止后不执行排队中的其他工具，源码编辑走已有失败回滚流程。该保护针对本地参数校验错误，不改变网络重试策略。

## 独立行内登录（待行内联调）

实现依据用户提供的《招乎统一认证-API使用文档》与《开发指南》，使用 OAuth2 授权码模式，不依赖 leancode 的后端。使用现有 `auth.mode` 作为行内登录开关，当前保持关闭，不新增环境变量。

| 使用阶段 | 配置文件中的 `auth.mode` | 行为 |
| --- | --- | --- |
| 当前部署 | `installation` | 使用原安装身份，不展示行内登录；保持原安装签名密钥，服务重启不会因此要求重新登录 |
| 当前本地开发 | `development` | 使用开发身份，不要求行内登录；仅限非生产环境 |
| 行内联调及正式启用 | `external` | 使用行内登录；当前会话存于内存，服务重启后需要重新登录 |

当前 `config/service.json` 已为 `installation`，`config/service.local.json` 已为 `development`，无需额外配置 clientId 或 SSO 私钥即可按原模式使用。准备好联调参数后，按以下步骤开启；修改服务配置后需重启服务。

1. 注册 UIAgent 自己的 clientId，并登记 `https://<服务域名>/v1/auth/sso/callback`，不是插件页面地址。
2. 将 `config/sso.example.json` 的内容填写后放入 `config/service.json` 的 `auth.sso`。本地使用 `service.local.json`；同样为完整配置，不是局部覆盖。示例文件不自动读取，不能直接作为可用配置。
3. `baseUrl` 填认证网关根地址（代码拼接 `/auth-server/auth` 与 `/auth-server/token`）；`centerPublicKey` 使用对应环境认证中心公钥，`idTokenAlgorithm` 必须填写行内实际 JWT 的算法标识，拒绝 `none`。`issuer` 若平台提供则填写并精确校验。
4. `extensionIds` 填浏览器扩展管理页中的 UIAgent ID（32 位 a–p 字母），可登记多个开发/正式插件 ID。建议正式安装包使用固定插件 ID。它限定服务端可回传一次性票据的 `https://<插件ID>.chromiumapp.org/sso`，不需要在统一认证平台注册该地址。
5. 私钥只通过 `SSO_PRIVATE_KEY` 注入，支持原始 32 字节私钥的 Hex/Base64，不支持把 PEM/PKCS8 直接塞入此字段。管理员通过 `SSO_ADMIN_USER_IDS` 配置，值为认证后的完整 `sso:<openId>`；不读取客户端声明的角色，不继承旧安装身份的管理员资格。
6. 将 `auth.mode` 改为 `external`，重启服务、重新构建并加载带 `identity` 权限的插件。配置未齐或密钥无效时，登录入口不可用，接口不会回退到匿名/安装身份。

插件点击登录才调用 Chrome `identity.launchWebAuthFlow`。服务端生成 state 并绑定 HttpOnly/SameSite 浏览器 Cookie；成功验签、校验有效期和本应用 audience 后，给登记过的插件回传 60 秒一次性票据。插件校验自身 state 并携带独立随机 verifier 兑换会话，服务端核对 SHA-256 challenge。这里是 UIAgent 与插件之间的票据绑定，不声称行内 OAuth 服务已支持 PKCE。行内 access/refresh/id_token、签名私钥均不发给插件，插件只在受信任的 storage.session 中保存 UIAgent 会话。

身份验证遵循文档中 `aud[0]` 为 ClientInfo JSON 的形式，核对其中 id 等于 clientId；userId 使用 `sso:<openId>`，租户来自服务端配置。过期的身份令牌、错误签名、错误 audience/算法均拒绝。签名请求无 body，保留空 X-Content 行；Header 顺序固定为文档列出的 Accept、Content-Type、X-ClientId、X-Nonce、X-TimeStamp，查询参数与实际 URL 一致。

**联调必须核实的协议细节**：文档没有完整签名测试向量，需用行内实际样本确认 canonical header 大小写/顺序、查询编码、SM2 userId、签名 raw/DER 格式和 JWT alg。`signatureFormat` 与 `sm2UserId` 可配置，不尝试多算法降级；若请求与 JWT 使用不同格式，需明确后拆分配置。认证中心公钥不要跨环境使用。`sm-crypto@0.3.13` 及其传递依赖 `jsbn@1.1.0` 已固定，原依赖版本和校验信息保持。签名每次通过 pointPool 注入 Node crypto 的安全随机字节，避免 jsbn 在 Node 环境退回 Math.random；椭圆曲线运算和签名仍由库完成。

### 会话与旧副本

启用 `auth.mode=external` 后，当前版本按单实例部署：登录尝试、票据、会话和预览凭证只保存在服务端内存，进程重启后重新登录，不会丢失已经持久化的副本。浏览器重启后也重新登录。会话期限不超过配置期限或行内身份令牌剩余有效期；预览凭证只可 GET 指定副本的预览及资源，并依赖尚有效的会话。退出使当前会话及其预览凭证失效；已经加载的网页内容不会被远程擦除，已受理的编辑任务不会因退出自动取消。本版本不做行内全局退出，不会让用户退出其他行内应用。

登录后可点“关联旧副本”，确认将当前浏览器旧安装身份的副本及历史关联到当前账号。服务端同时验证 SSO 会话、旧安装签名凭证和每个副本的原 owner/tenant；逐副本通过现有 COS 持久化提交，不更改正文/Revision。操作每批最多 100 个，部分失败会反馈数量，可重新执行；正在编辑的副本不转移。关联不是全库原子事务。服务端需保留原 `INSTALLATION_TOKEN_SECRET` 和旧租户配置；旧凭证过期、换过密钥或丢失时，不能仅凭旧 userId 自助认领，需管理员另行迁移。登录本身不会自动重写原数据。

### 当前验证边界

clientId、应用私钥、实际 JWT/签名样本未提供，尚未连接行内认证平台；类型检查/构建不能替代行内联调。准备好配置后需验证：首次登录与已有 SSO 登录态、取消/过期回调、错误配置拒绝、旧副本关联、非管理员日志权限、预览访问与退出失效。未按本节内容声称这些真实流程已通过。

参考：[Chrome Identity API](https://developer.chrome.com/docs/extensions/reference/api/identity)、[sm-crypto](https://github.com/JuneAndGreen/sm-crypto)。


## 插件个人设置

右侧工具栏底部的齿轮进入设置页，返回后继续当前对话。复制用户 ID 与管理员运行日志入口集中到设置页；行内登录开启后，退出登录和关联旧副本也在账号区操作。模型快捷切换与独立技能入口继续保留。

个人设置包含模型选择、发送快捷键及已完成执行过程的默认展开方式，按当前服务与用户保存在浏览器本地，不跨设备同步。默认 Enter 发送、Shift + Enter 换行；可切换为 Ctrl / Command + Enter 发送。输入法选字时的 Enter 不发送。执行中的进度始终展示。

恢复默认设置仅清除当前用户在当前服务下的上述偏好，不改变独立技能面板中的技能开关，也不清除身份凭证、副本、历史对话或草稿。任务进行时不允许切换模型、退出账号或恢复设置。服务地址只读；检查连接验证当前服务与身份，不能据此认定模型调用或 COS 存储可用。检查更新沿用现有更新接口和下载流程。
