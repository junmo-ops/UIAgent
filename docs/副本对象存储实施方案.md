# 副本对象存储实施方案

日期：2026-09-23。状态：方案已确认，代码已按第一版边界实现；尚未完成行内验证。实施配置见《副本对象存储部署说明》。

## 1. 要解决的问题

服务更新、容器替换后，用户已经保存的副本、源码版本和对话仍可访问。

当前 Dockerfile 将副本写到 `/opt/deployments/data/source-workspaces`，服务启动只创建缺失目录，不主动清空数据。若目录没有持久化挂载，容器替换就无法保留旧文件；线上挂载尚未直接核验。用户确认平台支持 COS／S3，因此采用对象存储方案。

直观理解：对象存储保管正式数据，服务本地只保留可以重建的工作副本。更新服务时，重新从对象存储恢复数据。

## 2. 建议确定的范围

| 项目 | 第一版决定 |
| --- | --- |
| 正式存储 | 私有 COS／S3 桶，使用 UIAgent 专用前缀，不与参考项目的制品目录混用 |
| 存储单位 | 每份副本对应一个完整压缩对象；内含全部历史，不把一次源码 Revision 等同于一个对象 |
| 本地目录 | 已提交数据的缓存和临时编辑区；不能作为远端失败时的备用正式存储 |
| 保存成功 | 对象存储写入已确认；本地写入完成不等于保存成功 |
| 服务形态 | 单进程、单写入实例；同一副本的所有写操作串行化 |
| 恢复方式 | 启动时分页列举并恢复全部副本，恢复完成后才允许业务请求 |
| 插件 | 不增加存储配置入口，不接触密钥；优先沿用现有接口和错误展示 |
| 登录与归属 | 保留现有 ownerId、tenantId 和鉴权；公司登录另行推进 |
| 日志 | 独立诊断日志不在本次持久化范围，应另接平台日志或归档 |

保存范围包括 `workspace.json`、当前源码与编译产物、作者样式和资源引用清单、布局索引、所有保留的 revisions、会话与对话、任务接受记录和终态。图片和字体等外部资源仍遵循现有引用方式，本次不保证网页离线可用。

本次不做多实例写入、跨区域容灾、回收站、自动恢复模型执行，也不改变现有历史版本保留规则。

## 3. 复用与自建边界

参考 `/Users/moxiaojun/个人/leancode-vscode-plugin/src/modules/codeRiskScan/artifacts/s3Downloader.ts`，复用其 S3 SDK 接入方式：`aws-sdk@2.1184.0`、自定义 Endpoint、Bucket、Region、路径式访问，以及可选 sessionToken。

用户已确认该版本及所需依赖在行内可用，存储参数由部署时配置。参考实现只有下载行为，不能据此推定凭证有上传、列举和删除权限。参考代码关闭证书校验的做法不沿用；使用正常证书验证和部署环境认可的 CA。

SDK 负责请求签名、传输和有限重试；使用已确认行内可用的 `fflate@0.8.3` 负责 ZIP 打包与解压，无新增传递依赖。项目自建副本快照格式、提交协调、缓存恢复、归属检查和迁移工具，不自建 S3 协议客户端。

两份锁文件只增加必要依赖及其依赖闭包，保留已有行内版本、下载地址和完整性信息；导出过程不重新解析版本。

## 4. 对象格式与提交点

建议对象路径：`<prefix>/v1/workspaces/<workspaceId>.zip`。归属信息保存在归档中的工作区清单内，继续由服务鉴权；对象路径本身不是权限控制。仅支持 ZIP，不保留 `.json.gz` 兼容读取；切换前将旧归档备份移出工作区前缀，或使用新前缀。

ZIP 直接保存源码、历史和会话文件，解压后无需 Base64 解码。额外的 `__uiagent_archive__.json` 记录格式版本 2、workspaceId、唯一 commitId，以及各文件相对路径、字节长度和 SHA-256。只收集副本正式文件，排除临时文件、锁文件和编辑暂存目录。读取时校验格式、ID、路径、大小、哈希及工作区必要文件，拒绝符号链接、重复路径和路径越界。

同一副本使用一个固定对象键，通过一次完整 PUT 替换旧对象。它是唯一提交点，不另外维护需要同步更新的全局列表或“当前版本”指针。完整版本历史已经包含在该对象内。

这是本方案对早期“多个不可变文件对象加清单指针”设计的替代：第一版选择较少的远端操作和较简单的恢复流程，接受完整上传的成本。此方案要求行内实现支持完整对象替换，以及 PUT／DELETE 后可靠的读取和列举可见性；必须在行内验收，不把所有 S3 兼容产品视为行为完全相同。

## 5. 普通保存流程

创建、重命名、会话增删、对话保存、源码提交、撤销、重做、重置统一经过提交协调层：

1. 获取该副本的写入锁，读取最近一次已确认数据。
2. 在隔离的暂存目录执行修改；读请求继续读取已提交缓存，不暴露暂存内容。
3. 校验并打包完整副本，生成 commitId，上传固定对象键。
4. 确认远端提交后，切换本地缓存到新内容，再返回成功。
5. 上传明确失败则丢弃暂存修改，保留旧版本并返回存储错误；禁止静默退回仅本地保存。

远端已提交但缓存切换失败时，将该副本置为不可用并从远端恢复，不能继续提供旧缓存、声称回滚或重新运行模型。应保留真实提交状态，响应说明服务恢复未完成。

超时不等于失败：使用 commitId 读取核对；在无法确认前阻止该副本的新写入，保留待确认状态。重试只提交相同内容，不再执行模型、不重复应用修改。必须确保原请求及 SDK 重试结束，并完成状态核对后才放行后续写入；无法判定时返回暂不可用，不冒险继续。

## 6. Agent 任务与并发

- 接受任务时先持久化任务接受记录，确认后才返回 202 并启动模型；存储失败不启动模型。
- 使用现有 turnId 识别重复任务请求。提交结果未知时，客户端通过相同 turnId 查询，不能生成新任务来“重试保存”。
- 模型的编辑在隔离工作区中进行。执行期间允许读取已提交副本、查看进度和取消；其他副本写入独立进行。
- 为避免长任务覆盖并发修改，同一副本执行任务时，其他修改操作统一返回忙碌状态，包括重命名、对话和会话变更、撤销、重做、重置与删除。需要核对插件当前调用顺序，防止破坏正常对话流程。
- 模型进度保留在内存中，不为每条进度事件上传完整归档。已接受任务和最终结果必须持久化。
- 最终源码、版本、对话和任务终态在同一次提交中保存；远端确认前，模型工具的本地完成事件不得让用户看到“已保存”。
- 失败或取消且尚未提交时保留旧源码，尽力持久化对应终态；终态写入也失败时明确表示未持久化，不能伪造成功。重启后仍为运行中的记录显示为已中断，不自动重跑。
- 提交点之后收到取消时保留已保存结果；不能声称已经撤销。

## 7. 启动、读取和删除

### 启动与读取

S3 模式必须显式启用且完整配置。初始化检查连通性、权限和格式，分页列举专用前缀，在新的缓存目录恢复并校验全部副本，成功后启用业务路由。本地旧缓存不能合并回远端，也不能被当成恢复依据。

非空本地目录且没有可识别的缓存标记时，应停止并提示先迁移，避免把唯一旧数据当作缓存清理。远端恢复失败或发现损坏数据时初始化失败，不显示空副本列表。上线就绪检查需反映恢复结果，存活检查与就绪检查分开。

第一版采用完整恢复，所以启动时间随数据总量增长。运行期间只有当前实例写入，列表从已确认的本地索引产生；外部工具不得同时修改该前缀。已恢复的只读操作可在远端短时故障期间继续使用缓存，但写入不得假报成功。

### 删除

沿用永久删除的产品语义，任务执行中拒绝删除。获取副本锁后删除远端对象，核对其不可读取，再清理本地缓存和索引并返回成功；远端确认之前保留本地数据。删除结果未知时冻结该副本，确认后完成清理。重启时只恢复远端存在的对象，不能由残留本地目录重新上传已删除副本。

第一版使用单对象存储，因此不需要多对象删除清单。专用前缀必须核对桶版本控制、对象锁和保留策略：如果保留历史对象版本，普通 DELETE 不代表物理清除全部数据。不得把这种配置下的删除宣传为彻底清除；部署前需确定历史版本清理权限和流程，或使用符合现有永久删除语义的存储配置。

## 8. 部署配置和容量边界

普通存储参数统一放在 `apps/agent-service/config/workspace-storage.json`，随部署提供；不再增加普通参数环境变量。服务与迁移命令共用该文件，密钥只通过环境变量／Secret 提供。

| 配置 | 用途 |
| --- | --- |
| `mode` | local 用于本地开发，s3 用于行内部署 |
| `s3.endpoint` / `region` / `bucket` / `prefix` | 存储地址与专用隔离范围 |
| `cacheDirectory` | 可重建的本地缓存目录；相对路径基于服务包目录 |
| `s3.timeoutMs` / `archive` | 请求超时和归档容量上限 |
| `WORKSPACE_S3_ACCESS_KEY_ID` / `SECRET_ACCESS_KEY` / `SESSION_TOKEN` | 唯一需要新增的存储凭证环境变量；临时凭证需轮换并重启服务 |

存储账户仅授权专用前缀的读取、上传、列举、删除；凭证不下发插件、不写入日志。签名身份相关密钥仍须稳定保存，否则数据虽然存在，旧身份也可能无法访问。

全量快照会增加保存耗时、上传流量及压缩内存开销，随着源码历史增长更明显。接受记录也需一次完整上传。第一版需对真实副本统计大小、历史数量、单次保存耗时和空缓存启动耗时，据此确定容量上限及请求超时；超过上限必须在提交前报错，不能截断历史。不能在没有规模证据时承诺任意容量适用。

若实际规模无法接受完整上传／恢复成本，再改为不可变数据块与清单、按需恢复等方案；本次先不引入数据库、分布式锁或后台垃圾回收。

部署必须保证单写入实例，禁止滚动发布期间新旧实例同时写入。采用停止旧实例、启动新实例的发布方式；停机前停止接受新任务并等待执行结束，强制终止的任务按中断恢复。多实例属于后续独立改造。

## 9. 旧数据迁移与切换

1. 在旧服务仍可读取数据时备份完整 `source-workspaces` 目录到独立位置。插件导出只是当前快照，不能替代历史和对话备份。
2. 停止写入，等待或取消任务，完成最终备份。保留 workspaceId、ownerId、tenantId 及身份签名密钥。
3. 使用独立迁移命令先做只读预检查：统计数据、校验目录与格式、生成迁移清单；发现损坏数据则停止并报告，不静默跳过。
4. 将完整副本上传到选定前缀并回读核对。迁移仅在无运行服务写入时进行；同 ID 且内容一致可跳过，不同内容禁止覆盖。迁移可续跑，记录成功和失败清单，不删除源数据。
5. 用空缓存以 S3 模式启动服务，使用原身份确认副本列表、源码、历史与对话，继续编辑并撤销／重做。
6. 再执行一次真实部署，验证数据仍可用后才完成切换。旧备份按约定保留期处理，不在上线时自动删除。

启用 S3 后的回退必须继续读取对象存储；旧版仅本地存储的服务不能直接回退使用过期目录。如必须回退，应停写并先从最新远端对象导出兼容目录，校验后再启动。

## 10. 实施位置与验收

| 位置 | 计划变更 |
| --- | --- |
| 新增对象存储适配器与归档模块 | SDK、格式校验、上传读取删除、错误归类 |
| 工作区存储与提交协调层 | 隔离暂存、串行化、提交确认、缓存切换；收口所有写入 |
| 任务服务、执行器、进度存储 | 持久化接受记录与终态，避免过早报告保存成功 |
| HTTP 路由和启动入口 | 异步错误响应、忙碌限制、初始化和就绪状态 |
| 迁移命令、部署与导出文档、锁文件 | 迁移工具、配置透传、固定新增依赖 |

实现前应先列全写入入口，包括任务取消、失败收尾及读取旧任务时的状态修复，避免任何路径绕过提交协调层。不能仅把同步文件写入替换成不等待的后台上传。

遵循 AGENTS.md，不新增、不运行单元测试。实施阶段进行必要类型检查、构建与完整 diff 检查；以下功能由用户在行内真实环境验收：

- 空缓存启动和服务重新部署后，旧身份仍能访问源码、历史、对话并继续编辑。
- 重命名、会话变更、撤销／重做、重置在重启后保持一致。
- 拒绝写入、断网、上传超时不假报保存成功；未知提交结果恢复后不重复执行模型。
- 在接受任务后及提交前后终止服务，分别得到中断或已保存结果，不出现半份新版本。
- 删除后重启不复活；任务期间删除及其他冲突写入被阻止。
- 不同身份的数据仍隔离，桶对象不可匿名读取，密钥不进入插件或日志。
- 迁移中断可续跑，冲突数据不被覆盖；版本和依赖差异仅限本次必要新增。

## 11. 评审结论与剩余部署条件

建议按本方案确定“单实例、完整副本对象、远端确认后成功、启动恢复、显式迁移”的第一版边界。SDK 可用性已由用户确认，无需重复确认。本次实施仅修改服务端存储、迁移工具与部署材料，未修改插件代码。

部署时还需要提供存储参数和 Secret、确认前缀权限与对象一致性、明确版本保留策略，以及使用真实数据确定容量和超时。以上是部署与验收条件，不需要现在把密钥发到会话里。
