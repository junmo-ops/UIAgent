## 两个布局失败的证据

### L02：把源码顺序当成视觉位置

用户要求复制完整区块到原区块下方。Agent 声明的意图却变成“作为下一个同级区块插入”，随后调用 `clone_element`，使用 `position: after`，没有修改两列网格的布局规则。

浏览器坐标：原区块 `(x=24,y=24,width=202,height=153.828125)`；新区块 `(x=241.5,y=24,width=202,height=153.828125)`。两者 y 相同，新区块在右侧。截图与坐标一致。

回复却说“页面原为两列网格布局，因此副本会排到下一行的网格位置”。这不是工具执行报错，而是空间要求没有落实为真实视觉验收。应保留“下方”等相对位置约束并验证渲染结果，不能增加针对本案例的固定网格行、DOM 层级或关键词补丁。

### L04：修改了内部高度，遗漏外层裁切

Agent 读取的 `author.css` 有 `main { height:180px; overflow:auto }`，实际副本既有外层 `<main data-ui-agent-snapshot-stage>`，也有内部原网页的 `<main>`。Agent 只为内部容器添加 330px 高度覆盖。

执行后截图仍仅显示第一块及第二块的一小段边框，第二块标题和正文不可见。源码显示外层 main 也会匹配原始规则，这是外层裁切的直接排查线索；尚未独立采集外层完整计算样式来确认所有影响因素。即使只看内部内容，固定估计 330px 也不是“完整可见”的测量证明。

应同时检查源网页样式对副本外壳的影响，以及编辑后目标区域的祖先裁切链。本轮不修改产品布局代码，也不据此统一放宽容器高度。

## 后续优先级

1. 建立“需求中的视觉关系 → 浏览器测量 → 不符合时反馈模型修正”的通用闭环，先解决 L02、L04 这种实际失败。
2. 排查副本外壳与原网页样式的隔离，避免宽泛标签规则影响外壳。
3. 增加澄清后继续执行的多轮场景；当前 L01、L03 只走到提问，不能代表布局能力已覆盖。
4. 更新 S01 的技能前提后再单独验证；现有 S02 已提供真实 Python 执行证据。不要为了测试恢复过时产品技能。
5. 补入脱敏真实需求、复杂页面与交互任务，再评估泛化能力。当前只是五种简单布局和单次模型采样。
