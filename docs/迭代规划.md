## 降低插件更新成本

- 目标是减少用户更新插件的频率和成本，不追求完全免更新；不使用 iframe 托管插件界面。
- 侧栏聊天、选区和进度展示继续在插件本地运行，避免增加跨页面通信与生命周期管理。
- 模型策略、提示词和源码工具继续在服务端迭代；涉及本地交互、捕获逻辑或权限变更时正常发布插件。
- 副本管理、日志等独立页面可评估直接打开服务端网页，待公司登录接入时一并设计身份衔接和授权；当前仍保留本地页面，不通过 URL 传递长期安装凭证。
- 本次已撤回整体 iframe 远程化尝试，对应托管构建与消息桥不保留。

### 初步方案与范围

1. 插件提供公司账号登录、登录状态展示、退出和过期提示；不改变副本编辑的核心动线。
2. 优先在现有 Agent Service 接收登录回调、完成授权码交换并确认身份；插件通过绑定本次登录请求的一次性凭证领取会话，不要求用户安装本地回调服务。具体协议待后端资料确认。
3. 复用现有 `Authenticator` 和 `userId + tenantId` 归属校验；用户唯一标识及企业字段以认证服务确认的数据为准，不信任客户端自报身份。
4. 覆盖登录请求绑定与防重放、凭证有效期和续期、退出策略、接口及副本预览鉴权。公司凭证不进入 URL、模型上下文或诊断日志；应用密钥只保存在服务端。
5. 本地缓存按账号和服务环境隔离；退出或换账号后清理当前可见状态，避免显示上一账号的会话、草稿和副本内容。明确任务执行中退出或切换账号的处理方式。
6. 普通员工不沿用试点安装身份的默认管理员权限；运行日志访问权限单独确认。
7. 制定现有安装身份副本的迁移或保留策略，需要验证旧身份归属；不自动将历史数据绑定给任意登录账号。

不预设新增独立认证服务或数据库；是否需要持久化会话存储，应根据令牌撤销、重启恢复和部署实例数量评估。

### 验收重点

- 首次登录、已有公司登录态、取消登录、过期重登、退出登录流程可用。
- 不同员工的副本、会话、预览及本地缓存互不泄露；更换浏览器后同一账号仍可访问自己的服务端历史。
- 刷新插件、重启服务后，已保存的数据归属不变；登录会话按已确认的持久化策略处理。
- 非法或重复回调、过期凭证和无权限请求被拒绝；日志不记录认证秘密。
- 由用户在公司真实登录环境验证；遵循项目约定，不默认新增或运行单元测试。

### 当前基础与适配方向

普通聊天、意图路由和源码修改已使用 OpenAI 兼容调用链，主要通过 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_NAME` 配置；`MODEL_PROVIDER` 当前主要用于日志及健康检查，并非实际的模型切换开关。已有通用基础不代表候选模型已经完成兼容验证。

- 保留 Cline SDK 适配层、工具、安全边界及通用任务策略，不为每个厂商建立独立 Agent，也不加入页面或业务 Case 特化逻辑。
- 如现有兼容接口不足，增加薄的模型协议/能力适配层，处理思考参数、输出预算、消息回传和流式响应差异。
- 检查当前锁定 SDK 对推理字段（如 `reasoning_content`）的保留及回传能力，不能以单轮聊天成功代替多轮工具调用兼容性结论。
- 整理运行时中的 DeepSeek 命名，区分通用限流处理与行内网关特有错误处理；以实际网关协议为准。
- 模型密钥留在服务端；不默认新增依赖或升级 SDK，必要变更须按行内依赖版本约定确认。

### 分阶段范围

1. 首先选择一个行内已开放模型，完成服务端配置切换及普通聊天、意图路由、源码修改三条调用链的联调。
2. 补齐必要的思考模式、多轮工具调用、流式输出、停止、限流及异常处理适配，明确不同型号的能力限制。
3. 使用相同初始副本、提示词和任务预算进行对比；每次从同一基线开始，覆盖不同网页布局和复杂程度，避免前次修改影响结果。
4. 根据结果决定是否继续扩展候选模型。插件内模型选择、按会话选择模型以及不同调用链使用不同模型，列为后续可选扩展，不纳入首阶段默认范围。
