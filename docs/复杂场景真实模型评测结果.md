## 两个布局问题的证据

### C09：宽度忽略边框盒

模型生成的覆盖样式：

```css
.shell .pair { flex-direction: column; }
.shell .pair > .card { flex: 0 0 auto; width: 100%; }
```

原卡片有左右各 20px 内边距和各 1px 边框，使用默认内容盒。容器宽 846px，卡片最终宽 888px，多出 42px。外层预览宽 894px，实际内容宽 912px。修改后截图可见卡片右边界超出导航和提醒区域的对齐线。

这说明多轮“只恢复布局、保留文案”理解正确，但第一轮 CSS 修改本身不够完整。最终恢复不能抹去中间版本的缺陷。

### C12：新增节点的源码位置不等于指定视觉位置

模型把表单模块作为“使用帮助”卡片的下一个同级节点插入两列网格，没有相应调整布局关系。结果表单占右栏，原右栏说明落到下一行。

右侧说明的浏览器坐标从 `(596,80)` 变为 `(24,264)`，宽度从 274px 变为 548px。截图直接显示它已移到左下方。这与“在卡片下方、不改变右侧说明”的要求不符，也与 Agent 完成回复不符。

这是本轮独立复杂页面上的失败，与上一批 L02 呈现相同类型的问题，不能因为本轮 C01 复制成功就认为已解决。

## C12 测试误报与离线复核

原测试按完整可访问名称“订阅”找按钮，实际组件文本为“订 阅”，所以三次点击均未执行，后续状态检查也随之失败；不能据此断言表单逻辑坏了。

离线复核从 trace 提取实际生成的最终 HTML、覆盖 CSS，从成功工具记录重建 JSX，再用项目原有编译器和本地组件运行时加载。所有网络请求都被拦截，只提供记录与本地资源；不是重新生成代码，也不调用模型。使用允许文字间排版空白的按钮定位后，8 项点击/输入/状态检查通过，未观察到其他网络请求。

这是独立浏览器中的生成产物复核，**不是重新跑了一次完整插件 E2E**。原始 `evaluation.json` 和 HTML 报告保持不变，复核记录另存 `offline-replay.json`。后续主测试已采用同样的空白容忍定位，未为此重跑模型批次。
