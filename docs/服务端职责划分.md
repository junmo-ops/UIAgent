# 服务端职责划分

服务仍部署为一个 Agent Service。HTTP 路由和 Cline SDK 的工具接口不变，工作区内部通过组合拆分职责。

## 模块边界

以下文件均位于 `apps/agent-service/src/workspace/`。

| 模块 | 职责 |
| --- | --- |
| `store.ts` | 对外工作区入口；协调身份、编辑占用、资源和对话 |
| `editing-session.ts` | 单轮内存编辑：读取上下文、DOM/CSS/JSX 修改、校验、提交或释放 |
| `source-document.ts` | HTML 范围、结构、布局与样式上下文等源码操作 |
| `source-validation.ts` | HTML/CSS 安全、组件宿主和表格结构校验 |
| `module-compiler.ts` | JSX 编译、JavaScript 语法校验、模块注册关系校验 |
| `workspace-validation.ts` | 工作区持久化前的文件集合校验 |
| `file-storage.ts` | 文件与清单读写、路径边界、单文件原子写入 |
| `revision-history.ts` | 创建版本、清理重做分支、恢复指定版本 |
| `preview.ts` | 根据传入源码和样式信息组装预览 HTML，无文件写入 |
| `workspace-types.ts` | 工作区文件集合、清单及共享类型 |

## 一轮编辑

1. HTTP 层处理请求、鉴权和任务状态，经工作区入口创建编辑会话。
2. 工作区入口检查并占用工作区，读取当前源码和初始版本；初始化异常时释放占用。
3. Agent 使用编辑会话提供的工具修改内存源码。JSX 编译成功后才更新源码和产物。
4. 提交时通过回调调用版本管理。编辑会话不直接访问磁盘。
5. 提交成功或回滚时释放编辑占用。预览模块独立读取调用方提供的数据，不触发 Agent 或创建版本。

版本文件格式、接口路径和默认编辑行为保持不变。原有原子写入以单文件为单位，本次拆分不引入跨文件事务保证。

## 后续修改放在哪里

- 调整 JSX 编译选项：`module-compiler.ts`。
- 增加源码工具：`editing-session.ts`；通用 DOM 操作放在 `source-document.ts`。
- 调整版本切换：`revision-history.ts`。
- 调整样式或脚本加载：`preview.ts`。
- 调整文件读写：`file-storage.ts`。

避免让底层模块反向依赖 `SourceWorkspaceStore`。编辑会话通过明确的提交、布局读取和释放回调与工作区入口协作，不把完整 Store 传给工具。

自动候选渲染验证、几何验证及自动修正链路已移除，不再有实验开关。正常编辑保留结构化意图、源码校验、JSX 编译及直接版本提交；实际视觉效果由用户验证。

## 任务生命周期与恢复

- `tasks/source-turn-service.ts` 集中管理任务接收、同副本互斥、取消控制器和异常释放。HTTP 路由不再自行维护任务 Map；Agent 执行由独立的执行编排模块提供。
- `tasks/source-turn-executor.ts` 负责一轮修改的执行编排：读取会话、创建编辑会话、调用 Agent、保存结果及发布终态；不依赖 HTTP、身份认证和浏览器 API。诊断日志写入失败会记录服务端错误，不再将已保存修改改报为任务失败，也不会阻止异常任务返回终态。
- `progress/source-turn-progress-store.ts` 将 Agent 事件转换为用户进度，保留活跃任务的内存状态，不因终态缓存数量限制而淘汰运行中的任务。
- `tasks/turn-progress-storage.ts` 在每个副本的 `turns/` 目录保存任务记录，文件名使用 turnId 的 SHA-256；开始、取消请求、保存确认、最终结果落盘，模型文字增量不逐条写盘。
- 重启后首次查询遗留运行任务时，返回 `SOURCE_TURN_INTERRUPTED`，不自动重新执行模型，不推断未确认修改是否提交。插件重新读取正式副本并刷新预览。已保存终态可重新读取。
- 任务记录随副本永久删除；独立诊断日志的删除规则不变。历史任务的完整执行现场不会恢复，未采用分布式锁，不支持多个服务进程共享同一数据目录并执行任务。
- 任务记录采用单文件原子替换，但源码、会话、日志和任务状态之间仍没有跨文件事务；一致性提交属于下一阶段。

## 安装身份权限

安装身份默认只有 `user` 角色，不再自动获得全局日志权限。`INSTALLATION_ADMIN_USER_IDS` 配置管理员安装身份 userId（逗号分隔）；持有自己的身份凭证可通过 `GET /v1/auth/me` 查询身份。服务重启后按配置重新计算角色，不需要重新签发已有安装凭证。本地 development 模式仍有管理员权限，不用于公开部署。

## 插件端结果处理边界

`apps/extension/src/sidepanel/source-turn-result.ts` 统一首次执行与恢复执行后的正式任务结果处理：完成、澄清、取消、失败，以及进程中断后的正式副本刷新。通过注入刷新、消息保存和澄清状态更新操作与界面连接，不直接依赖 React 或 Chrome API。实验性候选流程及其轮询、预览切换、修正逻辑已删除。

依赖检查约束工作区领域层不反向依赖任务编排，任务编排不反向依赖 HTTP 入口或插件代码。后续增加任务行为应优先修改对应模块，而不是重新堆回路由和侧栏组件。

## 实验链路移除边界

已移除候选版本 API、候选发布、渲染任务及租约、截图证据上传、浏览器观察命令、模型几何验证、自动修正和对应协议。原页面捕获、A/B 样式生成、用户主动截图导出、结构化意图与布局范围检查、正式版本与撤销/重做均保留。旧候选数据不执行迁移或自动删除，旧候选 URL 不再提供服务；请回到正式副本。插件和服务端需同步更新。
