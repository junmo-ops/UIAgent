# UIAgent B 副本真实验证清单

日期：2026-09-07  
目的：在真实浏览器中确认 B（原始规则 + 覆盖层）是否比冻结计算样式副本更适合还原与连续编辑。本文记录人工验收，不把本地单元测试当作视觉结论。

## 1. 执行前确认

- 使用当前已部署的 Agent Service 与最新构建的浏览器插件。
- 默认直接提交模式：`CANDIDATE_RENDER_VALIDATION_ENABLED=false`。
- 创建副本时默认应打开 B。若需要对照 A，服务端需显式启用 `REPLICA_A_ENABLED=true`，再从副本管理页打开 A 基线。
- 每个样本使用相同浏览器缩放比例、同一窗口尺寸；记录页面 URL、创建时间与副本 ID。
- 从原网页新建副本。旧副本没有完整的原始样式清单，不能作为 B 的验证样本。

## 2. B 初始还原对照

选择三个互不相同的真实页面，每页只记录事实，不针对具体站点做代码调整：

1. 常规内容流页面：正文、表单或列表为主。
2. flex 或 grid 布局页面：包含多个并列区域、卡片或工具栏。
3. 定位或滚动页面：包含侧栏、弹层、固定工具区或局部滚动容器。

对每页执行：

1. 打开原页面，截取完整窗口截图。
2. 新建副本，打开 B 预览，在相同视口截图。
3. 如已启用 A，再打开 A 预览并截图。
4. 检查下列项目，分别记录“通过 / 不通过 / 无法判断”和简短现象：
   - 页面主结构、字体和背景是否加载；
   - 关键区域的相对位置、间距、宽高和折行；
   - 图片、图标、字体及外链样式是否缺失；
   - 横向溢出、异常滚动条、遮挡、裁切；
   - B 相比 A 和原页面的差异。

通过标准：B 能正常展示主结构，并且没有新增会妨碍阅读或编辑的明显遮挡、裁切或横向溢出。若存在差异，记录差异区域和截图，不根据单一页面新增特判。

## 3. B 直接编辑验证

在上述样本中选择至少三个需求，覆盖以下不同类型：

1. 文本或属性修改，例如按钮文案、提示语、默认勾选状态。
2. 结构修改，例如新增、复制、移动或删除一块页面内容。
3. 布局或样式修改，例如间距、对齐、尺寸或响应式区域。

每条需求执行：

1. 记录用户原始输入和创建副本后的基线截图。
2. 在侧栏提交需求，等待结束；保存最终截图与日志 Trace ID。
3. 观察实际结果是否符合需求，并检查目标外区域是否出现遮挡、裁切、溢出或错误换行。
4. 再连续完成两轮编辑，然后执行撤销和重做各一次。
5. 记录耗时、模型调用轮数、是否需要人工再次描述或修正、最终是否接受。

通过标准：每条需求的实际页面结果可接受；连续编辑、撤销和重做能回到对应版本。模型完成提示不等于通过，必须以页面截图和人工观察为准。

## 4. 候选渲染验证实验（单独执行）

这一项仍是实验能力，只有在前三项稳定后再启用。将 `CANDIDATE_RENDER_VALIDATION_ENABLED` 配为 `true` 并重启服务，然后选择一条布局需求执行。

记录：

- 任务是否进入“检查效果”阶段；
- 浏览器是否收到并完成渲染任务；
- 发生布局问题时，系统是否给出明确失败或无法验证，而不是直接宣称成功；
- 自动修正次数、总耗时、最终提交状态；
- 关闭侧栏、切换标签页或服务重启后，候选是否错误提交。

通过标准：候选版本、观察和提交对应同一版本；缺少浏览器证据时不提交正式 Revision。当前模型没有图片输入，因此这里只验证几何与就绪状态，不把它称为视觉审查。

## 5. 反馈给开发的最小材料

每个失败或不确定样本提供以下内容即可：原始需求、原页面与副本截图、工作区 ID、Trace ID、创建时间、是否 B 或 A、复现步骤。无需导出完整网页源码或包含敏感业务数据的日志。
