## 二、项目简介

本项目面向产品经理缺少设计资源、难以准确表达页面改动的问题，提供一款运行于 Chrome Side Panel 的 AI UI 需求示意助手。

插件可以将当前真实页面冻结为安全的静态源码副本。产品经理在副本中选择目标区域，通过自然语言描述“在哪里增加什么、内容是什么、样式如何、希望展示何种状态”，通用源码 Agent 随后按需读取和修改副本中的 HTML/CSS，生成贴合原页面视觉的需求示意，并支持多轮调整、撤销重做和截图导出。

项目的目标不是让 AI 修改生产系统或生成可直接上线的业务代码，而是把产品经理的自然语言快速转化为可查看、可讨论、可交付的 UI 示意，帮助产品与研发更高效地对齐需求。

当前已完成以下关键链路：

- 固定测试页和真实业务页面的静态快照生成；
- 跨电脑快照导出与导入；
- Cline 通用源码 Agent 与 DeepSeek 模型接入；
- HTML/CSS 受控编辑、版本管理、撤销与重做；
- 页面选区空间锚点与新增模块位置校验；
- Agent 实时进度与全链路日志；
- 腾讯云 CloudBase 远程部署；
- 28 个测试文件、136 项自动化测试全部通过。

## 四、项目背景、目的与意义

### 4.1 业务背景

在 PC 端产品需求编写中，产品经理经常通过原型、截图和文字说明页面调整。当需求涉及控件相对位置、组件样式、弹层状态或复杂布局时，纯文字容易产生理解偏差；制作高保真原型又需要较高的设计和搭建成本。

例如，产品经理希望在订单页面增加一个筛选项，需要描述它放在哪里、包含哪些选项、宽度是否与已有筛选项一致、下拉框展开后展示什么。研发仅凭文字往往无法一次理解最终效果，需要和产品反复确认。

如果产品经理能直接在现有页面的静态副本中生成一张修改后的示意图，研发就能直观看到“改哪里、改成什么、最终状态是什么”。

### 4.2 核心痛点

1. 简单 UI 调整也要从空白原型重新搭建，存在工具切换和重复劳动。
2. “放在右侧”“样式一致”“在页面底部增加模块”等描述缺少真实页面结构和空间参照。
3. 直接修改运行时 DOM 容易受 React/Vue 重新渲染影响，修改结果不稳定。
4. 每轮把整页 DOM 和样式发送给模型，会产生较高 Token 消耗和响应时延。
5. 开放式 Agent 如果拥有脚本、网络或任意文件权限，可能引入接口调用、数据泄露和页面破坏风险。
6. 如果每遇到一个失败案例就增加专用规则，能力会逐渐演变为不可维护的关键词系统。

### 4.3 项目目标

项目希望把“重新制作原型”简化为“在真实页面副本上描述修改”：

1. 产品经理从当前业务页面一键进入静态副本。
2. 在副本中选择目标区域并输入自然语言需求。
3. AI 在受控范围内修改静态 HTML/CSS 源码。
4. 用户通过多轮对话继续优化效果。
5. 最终导出截图，作为需求文档和研发沟通材料。

项目同时坚持三条边界：原业务页面只读、模型能力受控、静态副本不具备真实业务操作能力。

## 五、价值分析

### 5.1 效率价值

产品经理不再需要从空白原型开始搭建常见页面改动，而是直接复用真实页面的结构、布局和视觉语言。对于新增筛选项、按钮、提示、字段、表格行和信息模块等需求，可以更快获得可评审的示意结果。

### 5.2 协同价值

输出结果比纯文字更准确地表达位置、内容、组件形态和展示状态。研发可以结合修改后的页面截图和自然语言要求理解需求，减少围绕 UI 细节的重复确认。

### 5.3 安全价值

静态副本会移除原页面脚本、事件、接口、表单提交和跨页面导航能力。AI 修改的是隔离工作区中的 HTML/CSS，而不是生产页面，也不能执行真实业务操作。

### 5.4 跨环境价值

当业务页面只能在另一台电脑或隔离网络中访问时，可以在可访问页面的电脑上导出版本化快照包，再通过合规方式传输到开发电脑导入。快照包不包含 Cookie、本地存储、脚本和接口能力。

### 5.5 当前可验证成果

| 跨电脑链路 | 已跑通 | 支持快照包导出、传输、导入和重新创建工作区 |

### 5.6 后续量化口径

当前成果主要证明技术链路和安全边界可行，尚未形成生产级业务收益数据。进入内部试点后，建议统计：

- 单个 UI 需求从描述到形成可评审示意的耗时；
- 产品与研发围绕 UI 细节的确认轮次；
- 因需求理解偏差产生的返工次数；
- 研发一次理解率；
- Agent 首次完成率和平均修改轮次；
- 不安全操作的策略阻断率。

建议首轮选择一个低风险、已脱敏的内部系统，连续收集不少于 30 个真实 UI 需求样本，并与原有文字或原型方式做同类任务对照。

## 六、项目方案

### 6.1 总体思路

项目采用“浏览器捕获层—静态源码工作区—通用源码 Agent—受控文件工具—预览与版本层”的闭环架构。

原业务页面始终只读。插件捕获浏览器当前已经渲染的页面状态，移除活动能力，并生成可维护的静态工作区：

```text
index.html
snapshot.css
outline.json
source-map.json
```

用户在副本中选区后，Agent 不接收整页 DOM，而是通过页面结构摘要、搜索和局部读取按需获取上下文，再修改 HTML/CSS。每次修改必须通过格式、安全和空间范围校验，成功后才形成新的 Revision。

> 【图片占位：图 2】页面快照、隔离工作区、源码 Agent、校验预览与交付闭环。

### 6.2 核心操作流程

1. **进入副本**：产品经理在普通 HTTP/HTTPS 页面打开插件，确认进入副本编辑。
2. **冻结页面**：插件捕获当前页面、表单值、勾选状态、已打开弹窗和可见样式。
3. **安全裁剪**：移除脚本、事件、接口、表单提交、远程导航和外链资源。
4. **生成工作区**：Agent Service 把快照编译为独立 HTML/CSS 源码和语义索引。
5. **选择区域**：用户在副本中选择要修改的元素或局部容器。
6. **描述需求**：用户用自然语言说明新增、修改、移动、删除或展示状态。
7. **源码编辑**：通用 Agent 搜索和读取相关源码，调用受控工具完成修改。
8. **安全校验**：服务检查 HTML/CSS、危险内容、文件范围和新增模块位置。
9. **形成版本**：修改成功后生成 Revision，并刷新副本预览。
10. **继续调整**：用户可继续对话、重新选区、撤销、重做或恢复初始版本。
11. **交付结果**：用户导出当前可视区域截图，或导出快照包供另一台电脑继续编辑。

### 6.3 当前功能范围

- 真实页面静态快照；
- 当前表单值、勾选状态和已打开弹窗冻结；
- 副本页面元素选择与空间锚点；
- 文案和可见样式修改；
- 按钮、文本、链接、输入框、下拉框、单选、多选、标签、提示条、表格和表单模块等常见内容新增；
- 元素结构移动和克隆；
- 静态弹层和展开状态展示；
- 多轮对话；
- 撤销、重做和恢复初始版本；
- 当前可视区域截图；
- 跨电脑快照包导出与导入；
- Agent 实时进度和日志查看；
- 本地服务与 CloudBase 远程服务切换。

### 6.4 暂不包含

- 真实接口调用和业务提交；
- 跨页面业务流程；
- 执行原页面 JavaScript；
- React/Vue 源项目还原；
- 生产代码生成和自动回写业务代码仓库；
- 多人在线协作；
- 完整还原 Canvas、视频、动画、跨域字体和所有复杂伪元素；
- 未经脱敏的敏感业务页面处理。

## 七、Agent 与技术架构

### 7.1 为什么采用通用源码 Agent

静态副本本质上是一组 HTML/CSS 文件，任务与通用 Coding Agent 修改代码高度相似。因此项目没有继续从零建设完整的上下文管理、Loop、记忆和工具调度能力，而是通过 Adapter 接入 Cline SDK，复用成熟的源码 Agent 基础能力。

项目保留 Legacy Adapter 作为回退，并把模型调用层设计为可替换接口，当前接入 DeepSeek。

### 7.2 通用层与业务层分工

| 层级 | 主要职责 | 建设方式 |
| --- | --- | --- |
| 通用 Agent Runtime | 模型调用、上下文、循环、工具调度、错误处理、收敛 | 优先复用 Cline SDK、Vercel AI SDK |
| UI 源码业务层 | 页面语义、选区锚点、修改目标、样式与结构约束 | 项目自研 |
| 受控工具层 | 搜索、局部读取、样式读取、移动、克隆、Patch、校验 | 项目自研并限制能力范围 |
| 工作区层 | 文件、Revision、撤销重做、预览、跨电脑导入 | 项目自研 |
| 安全层 | 页面裁剪、路径隔离、CSP、敏感信息和危险内容校验 | 项目自研 |

### 7.3 受控源码工具

Agent 可使用的主要能力包括：

- 页面 Outline 和元素检索；
- 按 sourceId 检查元素；
- 局部读取 HTML/CSS；
- 一次读取完整样式规则；
- 移动已有结构；
- 克隆已有结构并保留样式；
- 精确文本替换；
- 受控 Patch；
- HTML/CSS 和安全校验；
- 新增元素空间范围校验；
- 提交、完成或请求用户澄清。

Agent 不能访问 Shell、任意网络、浏览器控制能力、其他目录或其他用户工作区。

### 7.4 渐进式上下文

模型不再在每轮接收完整 DOM 和全部样式，而是先获得页面 Outline、当前选区和轻量结构信息；需要时再搜索元素、读取局部源码或完整样式规则。

这种方式能够：

- 降低无关 Token；
- 减少超长 DOM 对模型判断的干扰；
- 让复杂任务围绕实际修改区域逐步展开；
- 把上下文读取过程记录到日志中，方便定位性能问题。

### 7.5 循环与收敛

源码编辑任务允许比简单 DOM 操作更多的工具调用。当前单轮默认最多 45 次迭代，最后 3 轮进入收敛阶段，停止扩展读取，强制 Agent 在“校验并完成”或“向用户澄清”之间做出选择，避免页面已经改完却因未调用完成工具而回滚。

对话记忆与源码 Revision 绑定。用户撤销到旧版本后，被撤销版本对应的对话不会继续发送给下一轮模型，避免旧需求污染新分支。

### 7.6 分层技术架构

1. **插件交互层**：WXT、React、Chrome MV3 Side Panel。
2. **快照捕获层**：读取运行态页面、表单状态、弹窗和计算样式。
3. **快照编译层**：安全裁剪、HTML 格式化、CSS 去重、Outline 和 Source Map。
4. **Agent Service**：Hono HTTP 服务、DeepSeek 模型调用、Cline Adapter。
5. **源码编辑层**：通用 Agent 和受控源码工具。
6. **工作区层**：文件、Revision、撤销重做、跨电脑导入与静态预览。
7. **安全层**：路径隔离、危险内容校验、CSP 和体积限制。
8. **可观测与评测层**：JSONL 日志、实时进度、Vitest 和挑战场景评测。

### 7.7 开源复用策略

项目遵循“成熟开源通用层 + 自研安全业务层”的原则：

- WXT：Chrome 扩展工程基础；
- React：Side Panel 用户界面；
- Hono：轻量 Agent Service；
- Vercel AI SDK：模型调用与 OpenAI-compatible 接口适配；
- Cline SDK：通用源码 Agent Loop 和工具调度；
- Zod：协议和边界校验；
- Vitest：自动化测试；
- Alibaba PageAgent：参考页面理解、元素映射和可见性处理思路。

必须自研的部分包括运行态快照冻结与安全裁剪、Source Map、静态工作区协议、选区空间锚点、受控源码工具、Revision 对话绑定、跨电脑快照包、CSP 预览和结果校验。这些能力直接决定产品安全边界和业务体验。

## 八、安全设计

### 8.1 最小授权

插件采用 `activeTab` 临时授权，不申请 `<all_urls>` 长期权限，仅处理用户主动打开并授权的普通 HTTP/HTTPS 页面。

### 8.2 页面主动去能力

捕获阶段会移除：

- `script`、`iframe`、`object`、`embed`；
- `on*` 事件处理器；
- 表单 action；
- HTTP/HTTPS 外链资源和远程导航；
- React/Vue 运行时标记；
- Cookie、Local Storage 和 Session Storage。

### 8.3 工作区隔离

Agent 只能访问当前 Workspace 中允许编辑的源码文件，不能读取仓库其他文件、其他工作区或操作系统目录。

### 8.4 预览隔离

静态副本通过 CSP 禁止脚本、接口、表单提交和页面导航，确保示意页不能转化为真实业务操作工具。

### 8.5 版本与恢复

每次成功修改形成一个 Revision。校验失败不提交；用户可以撤销、重做或恢复初始版本。撤销后，对应无效分支的对话上下文也会被截断。

### 8.6 可追溯

日志记录用户指令、Agent 操作摘要、工具结果、校验状态、Revision、模型调用次数、工具调用次数和耗时，并对 API Key、Authorization、Token、Cookie 和密码等字段脱敏。

当前 CloudBase 部署用于受控 Demo，正式试点前仍需补充统一鉴权、用户工作区隔离、持久化存储、自动过期清理、限流和日志访问权限。

## 九、关键难点与通用解法

### 9.1 从运行时页面生成可维护源码

浏览器 DOM 适合展示，却不适合 Coding Agent 反复修改。项目把运行态页面编译为格式化 HTML、去重 CSS、Outline 和 Source Map，使 Agent 可以通过搜索、局部读取和 Patch 完成复杂任务。

### 9.2 跨电脑快照视觉还原

单纯复制 HTML 无法完整保留计算样式、弹窗位置和运行态状态。项目通过固定原始视口画布、居中展示、计算样式冻结、伪元素保留、格式化空白处理、字体栈归一和单行文本保护，提高快照导入后的视觉一致性。

### 9.3 新增模块的位置判断

用户明确描述“页面顶部、页面底部、固定位置或悬浮位置”时，允许使用全局容器；没有明确全局位置时，系统默认围绕当前选中元素或其最近语义祖先定位。

新增元素在提交前必须调用 `validate_spatial_scope` 校验。局部需求中新增 `position: fixed` 会被拒绝；无法确定参照容器时，Agent 必须向用户澄清，而不是自行猜测。

### 9.4 复杂任务的 Agent 收敛

复杂源码任务需要多轮搜索、读取和修改，不能简单限制为少量模型调用。项目在提高迭代预算的同时增加末轮收敛区，避免无限读取或修改完成后不结束。

### 9.5 避免按案例逐条特判

项目不增加“订单行”“筛选栏”等业务专用工具，而是通过移动、克隆、样式读取、精确替换和空间校验等通用原子能力覆盖不同页面场景。问题按快照、定位、工具、Agent、校验和预览分层归因，通过回归集、挑战集和真实日志验证通用性。

## 十二、核心创新与竞争优势

### 12.1 从“修改运行时 DOM”升级为“编辑隔离静态源码”

静态副本把真实页面视觉转化为 Coding Agent 熟悉的 HTML/CSS 工程问题。复杂布局可以通过搜索和 Patch 逐步完成，刷新后仍保留修改，同时原业务页面始终只读。

### 12.2 通用 Coding Agent 与安全业务边界解耦

项目复用 Cline 的通用 Loop、上下文和工具调度能力，但只向 Agent 暴露当前 Workspace 内的受控工具。Agent 能力可以持续升级，页面数据、文件范围和提交规则仍由项目确定性控制。

### 12.3 选区驱动的空间约束

选区不仅用于告诉 Agent “改什么”，也作为默认空间参照。用户未明确全局位置时，新增模块必须围绕选区或最近语义容器定位，避免新内容被错误放到页面顶部或根节点。

### 12.4 跨电脑、可部署的完整使用链路

快照包解决隔离电脑之间的页面迁移，CloudBase 使其他用户只安装插件即可使用，不需要在每台电脑上安装 Node.js、pnpm 或启动本地 Agent Service。

### 12.5 可回滚、可追溯、可评测

Revision、撤销重做、对话分支绑定、Agent 日志、136 项自动化测试和挑战用例共同构成可持续迭代的工程基础。系统不仅展示“完成了什么”，也能解释“读取了什么、调用了哪些工具、为何失败、最终提交了哪个版本”。

## 十三、当前限制与待补充事项

### 13.1 当前限制

- 快照模式以静态 UI 示意为目标，不保证完整还原复杂动画、Canvas、视频和所有跨域资源。
- 当前 CloudBase Demo 尚未实现正式用户鉴权和多用户工作区隔离。
- 云端工作区当前使用容器文件系统，实例替换或重新部署后历史快照可能丢失。
- 页面数据会通过 HTTPS 发送到 Agent Service，当前仅适用于无敏感信息或已经脱敏的测试场景。
- 项目尚未形成真实试点的效率收益数据。
