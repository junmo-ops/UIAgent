# UIAgent 核心能力重设计与验证计划

日期：2026-09-05  
状态：架构提案；未实施、未通过原型验证。本文不替代现有运行配置。  
范围：重新定义核心能力、候选架构和决策实验，不修改产品代码。

## 1. 执行结论

产品方向暂予保留，现有实现不作为新架构的前提。推荐先验证“浏览器可观察的编辑事务”架构，而不是先选一个新的快照库或 Agent 框架。

核心决策是分离三种表示：

1. 保存表示：为恢复和渲染保留页面及资源。
2. 观察表示：向模型提供当前任务所需、有版本的结构、样式和视觉事实。
3. 修改表示：表达受控、可回滚的局部变更，不要求模型搜索和重写整个保存包。

三者可以共享 DOM 标识，但不应被一个巨大的 HTML/CSS 文件格式绑在一起。文件大小、模型输入规模与可编辑性分别度量。

近期推荐：以保留规则的安全 DOM 副本作为首个候选，以局部重建作为挑战者，冻结计算样式作为基线。先做获取质量筛选，再只让最有希望的两个候选进入编辑对照。没有实验结果前，不全面迁移，不建设自动多引擎路由，不增加多 Agent。

这是有条件的推荐：如果安全捕获无法保留必要规则，或局部编辑成本仍高，允许否定该推荐。不能用已有代码复用率替代产品效果。

## 2. 产品目标与尚待确认的边界

### 2.1 工作假设

目标用户为内部产品经理。目标工作是基于已有 PC 页面表达 UI 需求，交付可信视觉示意，减少原型制作和需求沟通返工。

首阶段交付物：固定视口下可预览、可连续修改、可撤销、可导出截图的需求示意。有限展示状态可用受控交互表达；不承诺真实业务行为。

成功不是“Agent 完成调用”，而是用户认为结果足够表达需求，且总投入少于原有工作方式。交互原型只是支持沟通的手段，不以生产代码质量作为验收项。

### 2.2 非目标

- 修改生产页面、调用真实业务接口、恢复原站点脚本或提交表单。
- 任意站点、任意复杂度、任意屏幕尺寸均无损还原的承诺。
- 从页面恢复原 React/Vue 项目、设计系统或完整应用逻辑。
- 第一阶段支持跨页面流程、生产代码交付、多个编辑引擎智能路由。

范围限制按能力和任务复杂度制定，不按网站、文案、业务 class、固定 DOM 层级制定。

### 2.3 需要产品证据核实的假设

| 假设 | 暂定选择 | 什么证据会改变架构 |
| --- | --- | --- |
| 主要价值来自局部及区域级修改 | 优先验证结构调整，而不只改字改色 | 用户主要需要全页重设计，则提高原型重建路线优先级 |
| 连续编辑比一次性生成更重要 | 至少验证三轮修改和撤销恢复 | 用户只要一张截图，则可减少 DOM 持续编辑要求 |
| 页面上下文必须保留 | 不静默裁掉选区外内容 | 用户明确接受局部画布后，才允许缩小保存范围 |
| 固定视口足以表达首期需求 | 每次捕获记录视口、缩放与状态 | 响应式是核心工作时，需要多视口验收与更丰富规则保留 |
| 企业内容可以送往批准的模型端点 | 仅批准端点、最小必要上下文 | 若不允许，需内网模型与本地/内网资源处理，不可绕过政策 |

不要求用户设计技术方案。后续收集 3–5 条真实需求及接受标准，用于核实上述假设；架构方向不由单条需求决定。

## 3. 独立推导的能力要求

UI 编辑至少需要四类证据：用户目标、当前页面事实、实际变更、修改后的结果。任何一类缺失，都不应由模型自行编造补齐。

由此导出下列不变量，与快照或 SDK 选型无关：

- 原页面只读；编辑仅作用于隔离候选副本。
- 基线获取质量先验收，不能让编辑 Agent 无限修复捕获损失。
- 模型观察必须标注版本、视口、采样时间及已知缺失，不以旧几何冒充当前几何。
- 需求存在重要歧义时可以只读调查，但不能写入；提出澄清后必须结束本轮执行。
- 用户目标、修改范围及重要视觉约束形成可追踪规格；模型不能用“已声明意图”代替解决歧义。
- 修改先落在候选版本；验证通过才能产生正式 Revision。
- 无法验证与验证失败是不同状态，都不能包装为成功。
- 不能以 DOM 前后顺序代替视觉位置，不能假定重叠或位移天然就是错误。

## 4. 架构：保存、观察、修改分离

```text
原页面（只读、用户授权）
    → 捕获包 + 缺失报告 → 安全副本 → 基线渲染验收
                                     ↓
用户目标 ↔ 需求规格 ↔ 单一规划 Agent ← 当前结构/样式/视觉观察
                                     ↓
                             受控候选变更事务
                                     ↓
                          实际渲染 + 分层验证
                             ↙             ↘
                 有限修正/澄清/失败       正式 Revision
```

### 4.1 保存表示：PagePackage

保存 DOM 当前状态、样式与资源清单、捕获视口、内容哈希、基线截图、能力报告及格式版本。具体采用原始规则、冻结规则还是局部生成内容，由候选方案决定。

资源按内容寻址；共享资源不应每个 Revision 重复存储。版本可以采用基线加补丁及定期物化，但必须保证可独立恢复，不仅保存脆弱的自然语言操作历史。存储压缩与模型上下文压缩独立处理。

捕获只代表已观察状态：虚拟列表未挂载的数据、关闭的远程弹窗、未加载资源不能被称为完整保存。能力报告需说明哪些内容缺失、静态化或不可编辑。允许用户明确接受非关键损失；关键区域失真则阻止进入编辑。

### 4.2 观察表示：Observation

以选区为入口，返回当前候选版本的对象标识、父子关系、角色/文字摘要、有效布局属性、边界矩形、滚动/裁切链，以及相关区域截图。必要时显式扩大观察范围。

大范围信息采用对象去重、分页和字段选择，不机械截掉祖先或兄弟。标明未返回的对象与续读入口；默认返回高价值属性，完整计算样式按需获取。历史矩形仅用于比较。

截图使用覆盖整个相关区域的概览和必要细节；不能只裁出新增对象而遗漏受影响邻域。观察范围可以大于修改范围。若选用模型不支持图像输入，必须明确视觉判断能力受限，不能通过文本矩形宣称完成视觉验收。

### 4.3 修改表示：ChangeSet

包含基线 Revision、需求规格版本、目标对象、原子操作、预期影响范围及前置条件。支持文本/属性、结构操作、局部 CSS 覆盖、必要的子树替换；底层如何存储由文档后端决定。

不新增“某业务卡片排几列”这样的工具。模型决定布局策略；执行器负责引用有效性、版本冲突、安全与原子性。复杂修改允许受控补丁兜底，但不开放任意脚本、Shell 或网络。

受影响范围不能仅按固定祖先数量计算。结合模型计划、实际渲染差异和布局依赖扩展观察；出现计划外的重大变化时返回模型判断，必要时请求用户批准扩大修改范围。

## 5. 候选载体及初步取舍

| 路线 | 机制与优势 | 主要风险 | 本轮角色 |
| --- | --- | --- | --- |
| A 冻结计算样式 | 保存当前属性结果，不依赖原样式文件可读取 | 表示膨胀、部分约束固化、结构编辑成本高 | 现有基线；不预先判死刑 |
| B 保留规则 + 局部覆盖 | 保留共享 CSS、变量与 DOM 状态，追加隔离修改层 | 样式和资源访问权限、级联、脚本移除后状态偏差 | 首选获取原型 |
| C 局部重建 | 基于页面证据重建目标区域，周围保留 | 边界拼接、跨区重排、连续编辑身份映射 | B 的主要挑战者 |
| D 视觉原型重建 | 不继承原源码，生成用于沟通的新文档 | 非目标区域保真、首次重建成本、重复编辑漂移 | 若全页设计成为主需求，再提高优先级 |
| E 直接修改原运行页面 | 省去副本获取，原状态可见 | 原脚本回写、真实副作用、历史恢复与安全风险 | 不作为生产首选，不在真实业务页试验 |

### 5.1 B 路线的必要细节

保留规则不等于 Ctrl+S。需要保存样式顺序、@import、条件规则、字体与图片依赖，处理运行时 style、CSSOM 修改、构造样式表及可访问的 Shadow DOM。不能靠仅保留“当前命中选择器”去掉条件规则，否则新元素和新状态可能丢样式。

跨域样式无法通过普通 CSSOM 读取时，不默认申请全站权限，也不把员工凭证交给服务器抓取。首先报告缺失；必要权限必须明确申请。不可读取区域可声明不支持，不能静默退回全量冻结后仍标记为 B 路线成功。

脚本移除后必须恢复控件当前展示状态，并重新验收。closed Shadow DOM、Canvas、跨域 iframe 等以能力缺口记录；栅格化若采用，只是明确标识的不可编辑区域，不能假称保留结构。

### 5.2 C 路线的必要细节

局部重建不能靠截图覆盖原区域来掩盖布局影响。重建区域必须参与正常排版，周围内容随真实尺寸变化。模型结合结构和布局选择编辑边界，边界不确定时澄清，不用固定向上两级祖先。

重建生成的新 DOM/CSS 需要保留稳定对象映射，后续回合编辑这份文档，而不是每次重新生成。重点验证表格、跨容器对齐、定位参照和滚动区等无法轻易切开的关系。

## 6. Agent 与工具选型

### 6.1 先采用单一规划 Agent + 确定性执行器

不假设复杂任务必须多 Agent。先减少证据缺口与串行寻址成本，避免多个 Agent 重复读取、互相转述造成额外时延。后续只有对照实验显示独立审查具有净收益时，才增加审查 Agent。

模型可在证据充分时直接规划，不强制所有任务经过相同数量的工具调用。初始上下文由系统提供当前选区摘要与能力边界，避免模型先 list_files 再从零寻找入口。

### 6.2 概念工具接口（不是本轮最终 API）

| 工具能力 | 输入/输出要点 | 不承担的责任 |
| --- | --- | --- |
| observe / expand | 候选版本、对象集合、所需字段 → 结构、实时布局、截图、缺失项 | 不猜用户布局偏好 |
| query | 结构/文本条件、作用域、分页 → 候选对象与证据 | 不把字符串匹配称为视觉理解 |
| clarify | 问题与可选方案 → 持久化等待状态 | 不把默认选项当用户回答 |
| propose_change | 需求规格、前置条件、原子变更 → 候选版本和变更清单 | 不自行提交正式历史 |
| render_and_check | 候选版本、规格 → 渲染证据与分层检查 | 不用 DOM 合法性代替需求达成 |
| finish / cancel | 版本及验证引用 → 提交或丢弃 | 不允许无证据覆盖失败状态 |

保留低层 DOM 工具作为后端能力；是否直接暴露给模型由实验决定。外观属性读取应返回浏览器有效值及必要来源，而不是仅抓某类 class 的声明。

### 6.3 运行时选择原则

复制开源源码用于内网分发不是架构问题。SDK 名称和历史口碑不作为运行契约正确的证据。

选型先用契约测试验证：澄清硬暂停、恢复上下文、取消传播、并行工具的终态互斥、结构化错误、模型请求和工具次数分离、可观察 usage、版本锁定、内网打包和许可证义务。能满足这些契约的现有运行时优先复用；不满足时再比较替换成本。

本稿未做最新开源版本和许可核验，不将历史调研中的“直接采用”视为当前结论。候选类别包括浏览器存档组件、标准浏览器自动化、CSS 解析器、状态机与模型适配库；原型前用当前官方资料确认支持范围、权限、许可证及离线依赖。Playwright 可作为渲染实验候选，但截图断言不等于语义验收；不自行实现浏览器布局引擎。

## 7. 状态、事务与部署边界

### 7.1 状态机

```text
observing → planning → awaiting_user → observing（新回复）
                    ↘ applying → verifying → committed
                                  ↘ planning（有限修正）
任一未提交状态 → cancelled / failed
```

awaiting_user、committed、cancelled、failed 对当前执行段为终态。澄清是挂起会话、结束执行段，不是一个可继续调用写工具的文本返回值。

工具入口和存储事务分别检查状态与版本；不能只要求 SDK 停止。并行调用由协调器串行处理状态变更，原子决定进入等待或允许写入，禁止澄清之后仍有在途写入提交。只有新用户回复绑定到对应 clarificationId，才创建新执行段。

正式提交需检查需求版本、候选哈希与验证证据哈希一致。浏览器显示版本、验证版本和提交版本必须相同。取消、浏览器关闭或超时不得自动提交半成品。

### 7.2 浏览器与服务的默认分工

首选实验分工：用户浏览器负责原页面获取和隔离副本渲染；服务负责模型调用、文档与事务存储。用户无需安装本地 Agent Service。实验自动化可使用受控浏览器，不要求每位用户部署浏览器服务。

浏览器负责渲染并不等于让原页面脚本执行。预览使用隔离来源/沙箱，资源本地化和严格 CSP；可信测量桥由应用控制，不混入页面提供的脚本。

渲染桥绑定工作区、候选版本、标签页和请求随机标识；过期回执拒绝接收。断线则等待恢复或失败，不能把上次结果当本次验证。

若用户浏览器渲染稳定性或后台执行受限成为瓶颈，再评估云端浏览器。云端的字体、操作系统与资源访问差异要纳入结果一致性验证，不能假定截图相同。

### 7.3 安全与数据

页面文字、属性和 CSS 均是不可信数据，不能作为 Agent 指令；页面中的“忽略规则/上传数据”等内容不提升权限。工具仅访问当前用户工作区，不允许任意 URL、路径和脚本。

CSS 资源也可能触发外部请求，必须解析、重写并限制所有资源入口，不只删除 script。捕获凭证、员工数据及截图的发送范围需要内网政策批准；不复制 Cookie/Authorization 到副本或日志。界面用户隔离不替代服务端访问控制。

## 8. 验证：三个门槛，不是一个布尔值

### 8.1 获取验收

比较原页面与未编辑副本，在相同视口、字体就绪、滚动位置和状态下采样。记录文字/控件状态、几何、截图差异及资源缺失。动画或不稳定区域只能以有记录的稳定性规则处理，不能为隐藏失败任意加遮罩。

关键区域不合格则捕获失败；不得启动编辑来偷偷补偿。捕获成功率单独报告，不能只统计成功进入编辑的页面。

### 8.2 候选验证

- 协议与安全：合法结构、资源策略、事务版本、权限。
- 需求约束：内容、数量、相对位置、对齐、顺序等来自明确规格的关系。
- 渲染事实：真实矩形、滚动尺寸、裁切链、有效样式、必要时命中测试。
- 视觉与非目标回归：相关区域截图及周边差异；模型辅助判断，最终效果由用户接受度评价。

重叠、换行、滚动、位移不自动判错。结合基线、需求和实际可见区域解释。包围盒交集不是遮挡的充分条件，像素差异也不是需求错误的充分条件。确定性验证与模型判断分别记录，不合并为无法解释的总分。

### 8.3 提交与人工接受

只有适用的自动检查和视觉审查完成，才提交 Revision；能力不足则报告未验证，不自动降低标准。用户是否接受单独记录，不能把机器提交计为用户成功。

人工评估使用固定量表：目标是否达成、重要外观是否一致、无关区域是否受损、还需多少修改。人工不再负责每次追踪工具链排查。

## 9. 可推翻架构的实验

### 9.1 实验集合

使用 12 个授权或合成页面：普通流、flex、grid、定位、滚动、混合布局各 2 个，来自多种实现方式，不复刻单一业务 DOM。8 个用于探索，4 个页面级保留作盲测；同一页面的变体不得跨集合泄漏。

准备 24 个任务，覆盖局部内容变化、增删/复制、区域重排、长文案适应、多轮编辑。其中安排明确需求与需要澄清的需求，至少 4 条三轮编辑链并验证撤销恢复。加入资源缺失、取消、标签页关闭和版本冲突等独立故障测试。

真实用户需求补入后冻结任务与接受标准。不能看到结果后改变通过定义。页面/内容/目标生成规则独立于业务关键词，所有修改作为一般能力实现。

### 9.2 分阶段避免混淆变量

1. G0 契约基线：修复/在实验框架中保证澄清、取消、事务和计量正确。保留旧实现结果作为历史参考，不让已知控制缺陷决定载体输赢。
2. G1 获取筛选：比较 A/B/C 获取和首次可编辑文档建立质量，计入 C 的重建时间。D 先做桌面审查；若产品证据需要，再进入原型。
3. G2 编辑对照：选择两个最有希望候选，共用模型、权限、观察/验证能力、任务和预算。保留 A 的代表性结果作基线。各候选允许必要后端实现差异，但记录差异，不能宣称完全隔离变量。
4. G3 消融：对胜出候选分别测试紧凑观察、实时视觉反馈的增益；每次只改变一个主要因素。随后才做模型对比，不同时换载体、模型与 Agent 框架。
5. G4 保留集：配置锁定后运行，每个任务重复 3 次，报告每次结果与波动，不挑最好的一次。原型集失败复盘后可重新实验，但不能继续称同一保留集为盲测。

探索性阶段可先每任务运行一次控制成本，进入决策门槛的结果必须重复。人工用户回复使用预先写好的情景答案，不能为某路线提供额外指导。端到端试用另行计入真实等待与纠正成本。

### 9.3 必须采集的指标

| 维度 | 指标 |
| --- | --- |
| 获取 | 成功率、关键区域失真、缺失能力、首次可编辑耗时 |
| 表示 | 原始/压缩包大小、DOM/CSS/资源占比、属性与规则数量、Revision 增量 |
| 模型 | 实际请求次数、输入/输出 token、缓存情况、失败重试、耗时与费用 |
| 工具 | 各工具耗时、有效返回大小、重复读取、被截断/分页情况 |
| 编辑 | 需求接受率、一次纠正内接受率、非目标损伤、三轮稳定性 |
| 验证 | 假通过、假失败、无法验证；人工与机器意见差异 |
| 价值 | 用户操作时间、机器等待、总完成时间，相比原有截图标注/原型方式 |

统计以页面和任务为单位报告，不把同一任务重复运行当独立用户样本。小样本只支持探索决策，不宣称生产成功率。

### 9.4 建议决策门槛（实验前可调整，非当前成绩）

- 安全/事务：所有故障测试通过；不能出现澄清后写入、跨工作区访问或验证前提交。
- 获取：至少 11/12 页面关键区域可接受；不支持的页面计失败并说明原因，不移出分母。
- 编辑：在通过获取的任务中，至少 80% 在一次用户纠正内被接受；另报包含获取失败的端到端成功率。
- 价值：任务级完成时间中位数不超过人工基线的一半；同时列出尾部耗时，不用平均数掩盖长任务。
- 可靠性：三轮链无不可恢复漂移；正式接受样本中没有重大非目标损伤。
- 相对优势：候选应提高质量或在质量不下降时显著降低成本；仅缩小文件不足以胜出。

先约定资源上限：一轮获取原型、一轮编辑对照；模型调用预算每任务相同，建议单次执行最多两次自动修正，超出报告未完成。预算具体金额由批准的模型价格和任务量确定，不在缺少价格时承诺工期或费用。

若所有候选获取都差，先解决/收缩获取能力；若获取好但编辑差，分析观察、载体与模型贡献；若局部重建也无法省时，收缩为辅助标注/局部示意或停止此路线。每轮结束必须有继续、调整或停止决策，不默认追加提示词。
