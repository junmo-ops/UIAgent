# 服务端离线导出

日常只修改业务代码时，在根目录运行：

```bash
npm run export:internal-service
```

输出目录仍为 `../uiAgent-package`，必须为空。导出不调用 npm、npx 或 pnpm，不访问公网或行内源，也不需要安装 node_modules。

导出复用主仓库 `pnpm-lock.yaml` 的版本、校验值和 peer 依赖关系，只留下三个服务端工作区的生产依赖入口，删除前端及开发依赖入口。底层 packages/snapshots 元数据原样保留，避免手工裁剪破坏依赖关系；其中未引用的元数据不会让生产安装额外安装前端包。

如果 package.json 中的生产依赖和锁文件不匹配，导出会在写入前失败。先使用项目规定的 pnpm 10.33.0 更新并提交主仓库锁文件，不要手工改锁文件中的版本号。

## 依赖变更后的行内预检

在能访问行内制品库的电脑上运行：

```bash
npm run check:internal-deploy
```

预检会创建临时部署目录，并通过行内源执行生产依赖 frozen-lockfile 安装。这一步需要网络，用于发现锁定版本不存在、tarball 404、完整性错误等问题。离线导出成功不代表行内依赖已经可用。

行外更新锁文件可能选中行内尚不存在的版本：应确认可用版本后调整依赖并重新生成锁文件，再做预检。导出不会自动挑选或升级版本，也不再使用 `UI_AGENT_LOCKFILE_REGISTRY`。

部署包中的 `.npmrc` 和 Dockerfile 仍指向行内源；离线导出不改变流水线安装依赖的方式。
